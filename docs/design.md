# 设计思路文档

> 本文档是项目设计层面的**单一事实来源**：机制定义、方案取舍、关卡曲线、AI 关卡 pipeline、架构决策都在这里。
> 任何玩法 / 规则 / 架构层面的决策变更，先改这里，再动代码（见 `AGENTS.md`）。
> 实现进度与时间线见 [iteration.md](./iteration.md)。
> 命名与视觉包装方向见 §10。

## 1. 比赛定位与总体策略

- 比赛窗口 2026-08-22 ～ 2026-08-31，产出纯 H5 小游戏，**关卡 ≥ 50**。
- 明确不做故事、不做美术包装——评审水分被砍掉，胜负手是机制本身。
- 评审对齐：玩法脑洞 / 50 关扩展能力 / H5 实现难度 / **AI 可参与程度**。
- 总体策略：
  - 找到「**10 秒能学会、50 关还没玩腻**」的机制，坚决不做大。
  - 技术上避开物理引擎、大量动画、联网、复杂 Roguelike；HTML/CSS/TS + Canvas，关卡全部 JSON 化。
  - 机制数量严格控制在 5 个左右，靠组合而不是靠堆新机关撑到 50 关。
  - 50 关不是 50 张不同地图，而是一条学习曲线：**教规则 → 理解规则 → 滥用规则 → 规则组合 → mastery**。
  - AI 参与不止于「AI 帮我写代码」，而是让 AI 进入**关卡工程 pipeline**（见 §7）——这是隐藏得分点。

## 2. 候选机制评估与淘汰记录

| 方案 | 一句话 | 结论 | 理由 |
| --- | --- | --- | --- |
| Echo Grid v1（延迟分身重放移动） | 过去的你沿路径复现移动，协作踩压力板 | **毙掉** | 与《星穹铁道》「黄金替罪羊」结构高度相似（延迟分身 + 重放输入 + 踩机关 + 到终点），近期且知名，评委认出即判「微创新不足」。加再多新机关也只会被理解为「黄金替罪羊 + 新机关」 |

| Rule Shift | 每隔几关改变按键语义 | 备选 | 脑洞大，但很容易从「聪明」变成「烦」，关卡设计要求高 |
| One Line CPU | 3~5 指令槽循环执行的小机器人 | 备选 | 50 关容易、适合 AI 生成，但同类游戏多（Lightbot 等），原创性弱 |
| 不要同时发生 | 暂停/恢复周期运动物体，让多系统相位同步 | 备选 | 有冠军相、视觉极简，作为后备方向保留 |

**关键教训**：机制撞车检查必须前置。任何候选方案定稿前，先检索近两年的知名同类机制；「同一抽象原理」可以保留，「同一玩法结构 + 同一表现形式」必须砍掉。

## 3. 定题结论：《109.5°》作为唯一提交作品（2026-08-25）

前期让 t3 与 chem 各做最小可玩原型，用「**第 5 关测试**」定题：

> 每个原型手画 5 个关卡。哪个让你在画到第 5 关时还在不断冒出「诶，这还能这样玩？」，就选哪个。

- 测试标准不是「第 1 关好不好玩」，而是**机制的组合空间是否持续产生新点子**。
- 最终选择 **《109.5°》**：它已用 50 张正式 JSON 证明“自然规律 → 新不变式 → 组合题”的持续产出；`t+3` 只有 10 关，且舒服思考所需的时间线 UI 成本更高。提交窗口只继续打磨 Chem，不再双线加关。
- `t+3` 不删除：保留为研发档与候选淘汰证据，只能通过显式开发查询参数进入；正常首页、游戏内导航、README 主叙事和比赛答辩均只呈现《109.5°》。共享骨架仍保留，因为它证明 solver / undo / 协议不是为单个成品硬编码。
- 本次定题不是按已投入代码量选择：Chem 仍须通过真人盲测；若盲测失败，只返工教学和反馈，不重新打开双原型竞争，也不新增外围机关。

## 4. t+3 规则定义（v0）

### 核心规则

> 你每次按下的方向键，会在未来某个延迟时刻**再次控制另一枚棋子**。

### 精确时序定义

- 第 `t` 回合玩家输入 `u_t`。
- 「当前」棋子立即执行 `u_t`。
- 延迟为 `d` 的回声棋子，在第 `t + d` 回合执行 `u_t`（每枚棋子有各自的 `d`）。
- 撞墙 / 撞出边界的移动：棋子原地不动，但**输入仍然消耗一回合**（回声队列照常推进）——这是刻意设计：被墙挡住的输入同样会进入未来的回声队列，是谜题的一部分。

### 胜负与局面

- 每枚棋子（当前 + 回声）各有一个目标格。
- **胜利 = 所有棋子同时位于各自目标格**（每回合结束后检查）。

### v0 已实现范围

5×5 棋盘；1 枚当前棋子 + 1 枚延迟 2 的红色回声棋子；墙；关卡 1（教学关，最短解 4 步）。

### 关卡格式决策：`hint` 教学字段（2026-08-23）

- 决策：关卡 JSON 增加可选 `hint: string` 字段（教学/点拨文案），由 shell 展示在棋盘外。
- 理由：新手教程不靠剧情与美术（比赛约束），只能靠「关卡顺序 + 极简文字点拨」。`hint` 是纯展示字段：不进引擎状态、不进 `stateKey`、不影响 solver，向后兼容（缺省即无提示）。
- 约束：`hint` 只写「点拨」不写「答案」——不直接给出解法序列，保护试错发现的空间。

### 关卡批次决策：01–10 教程批次（2026-08-23）

- 决策：先手工完成 01–10 教程批次（见 §6 细化表），全部经 `pnpm solve` 验证，且最短解长度需符合每关设计意图（断言进测试）。
- 引擎结论：**多回声、不同延迟不需要改引擎**——`echoes: T3EchoDef[]` 天然支持多枚不同延迟的回声棋子，复杂度完全由关卡数据承担。本批次零引擎改动。
- 工具决策：新增 `scripts/craft-t3.ts`（`pnpm craft:t3 <spec.json>`）：从「预期解序列」正向构造关卡（用真实引擎跑一遍序列，末位置即目标格），再自动跑 solver 核对可解性与最短解长度。这是 §7 pipeline「生成 → 校验」环节的第一块实现，供后续 40 关复用。

### 扩展路线（若 t3 胜出）

1. 多枚回声棋子，不同延迟（+2 / +4 / +6）——每次按键同时给多个时间层编程。
2. 回声瓦片：改变延迟、删除回声、旋转/镜像回声指令。
3. 压力板与门：回声可以替你踩板。
4. 棋子间碰撞规则（互斥 / 堆叠 / 推挤）——见开放问题。

### 开放问题

- 棋子之间的碰撞规则：v0 允许重叠，正式版需要定（重叠太宽松，互斥可能让回声规划更有趣）。
- 回声棋子被墙挡住时是否应有区别化的视觉/音效反馈。
- 是否需要「等待（空过一回合）」输入，以对齐时间层。

## 5. 《109.5°》（chem）规则定义（v0）

### 设计意图

**不做「有机化学游戏」，而是偷一个有机化学原理，伪装成纯游戏规则。** 全程不出现任何化学术语；玩家通过试错自己发现规律，玩到后面才意识到「这是立体化学」。这与此前乐理机制游戏的思路同源：题材与机制是同一个东西。标题《109.5°》（四面体键角）与化学味视觉是仅有的、被允许的泄露口（见 §10）；答辩时的揭晓时刻就是说破「你们玩的其实是 SN2 反应」。

### 化学映射表（仅开发者可见，不出现在游戏内）

| 化学原理 | 游戏规则抽象 |
| --- | --- |
| SN2 背面进攻（backside attack） | 只能从中心开口臂的正对面撞入；正面撞入无效 |
| Walden 构型翻转（inversion） | 撞入成功后中心四臂 180° 对调（N↔S、E↔W） |
| 离去基团方向 | 「开口臂」：攻击发生后翻转到对侧，决定下一次可进攻的方向 |
| 亲核试剂取代（Nu 进 / X 出） | 玩家手持基团撞入：装入正对攻击者的臂，开口臂基团换出到手中（v1，见下） |
| 共轭体系 / 共振传播 | 正交相邻且面对臂同色的中心连通：一处被翻转，震动沿连通链传导（v2，见下） |
| （后续）anti-periplanar 消除 | 预留：相邻两臂必须反向对齐才能触发消除 |
| （后续）环己烷 chair flip | 预留：FLIP 操作交换轴向/水平方向 |

### v0 规则

- 棋盘上有玩家（攻击者）与一个或多个「中心」。
- 中心有四个臂（N/E/S/W），各持一个颜色基团；其中一个臂是**开口臂**（可进攻方向的对侧标记）。
- 方向键移动玩家；玩家**撞向中心 = 尝试进攻**（玩家本身不进入中心格）。
- 进攻判定：玩家移动方向必须与开口臂方向**相同**（即从开口臂的背面一侧撞入）；否则进攻无效（不消耗回合）。
- 进攻成功：中心四臂 180° 对调（N↔S、E↔W），开口臂翻转到对侧；消耗一回合。
- 胜利 = 每个目标「某中心的某臂为某颜色」同时满足。

### v0 简化声明（重要）

v0 是**占位规则**，只用于验证协议与手感：进攻不携带/交换基团、离去基团不落到棋盘上、只有单一翻转操作。正式原型必须重新设计，候选方向：

- 攻击者从棋盘拾取游离基团，带入中心替换离去基团，离去基团弹落到攻击者身后——变成「基团搬运 + 立体化学」的空间规划游戏。
- 多中心联动、anti-periplanar 消除、环翻转等进阶规则按 §6 曲线逐步引入。

### v1 正式规则：基团搬运（2026-08-24 决策）

**背景**：01–10 批次的制关证据 + 试玩反馈确认 v0「进攻 = 纯翻转」的奇偶上限正是无聊根源——每中心仅 2 种构型，谜题退化为「路线 + 拨开关」，立体化学沦为贴皮。决策：按 v0 简化声明预留的方向，把进攻从「拨开关」升级为「**搬运 + 交换**」。

新规则（在 v0 基础上增量，**完全向后兼容**：不声明游离基团的旧关行为不变）：

1. 关卡可声明游离基团 `groups: [{pos, color}]`（可选，缺省空）。
2. 玩家走上游离基团格 = 拾取；手中已有基团则**交换**（手中基团落到该格，格上基团入手）。不新增按键，动作空间仍是四方向。
3. **空手进攻 = v0 行为**（纯 180° 翻转，不发生交换）。
4. **持基团进攻 = 取代 + 翻转**：进攻方向 d（= 开口臂方向，判定不变）；手中基团装到 **d 的对面臂**（即正对攻击者的那条臂，Walden 几何：进入者占据离去位的对面）；原 d 臂（开口臂）上的基团被顶入攻击者手中；四臂照常 180° 对调；开口臂翻到对侧。一句话教学：「你撞进去一个，撞出来一个。」
5. 胜利条件不变（目标臂颜色）；手中与场上基团不参与判胜。
6. 校验放宽：目标颜色只需存在于**本关任一中心臂或任一游离基团**中（原「必须在该中心四臂上」会禁止搬运关）。初始四臂互异约束保留；交换后允许同中心出现重复色。

关键结构性质（制关前推导、制关中确认，是 11 关起的设计基石）：

- **开口轴不变式**：开口臂只在自身轴上翻转（N↔S / E↔W），**轴永不变** ⇒ 每个中心永远只接受一个轴向的进攻。
- **轴臂 = 插槽，垂臂 = 奇偶锁**：持基团交换只发生在开口轴的两条臂上；垂直方向的两条臂只会彼此对调（v0 奇偶语义原样保留）。
- 推论 1：目标在垂臂 ⇒ v0 式奇偶谜题（撞 0 或 1 次）；目标在轴臂且该色不在本中心 ⇒ **强制搬运**（该色不可能凭空出现在轴臂上）。两类目标可同关混用。
- 推论 2：垂臂颜色**永远到不了**同中心的轴臂（垂臂只与垂臂互换）；轴臂 A 的颜色到对面轴臂 B 用空手翻转即可（奇偶）。
- 推论 3：同中心「自搬运」被结构排除——手中颜色永远来自当前开口臂，不可能凭自己把垂臂颜色搬进插槽。跨中心输入是唯一通路。
- 推论 4（手持不变式，11–15 制关中推导）：**手持一旦非空永不为空**——拾取、场珠交换、进攻换出都只是替换手中颜色 ⇒ 「空手翻转」的机会只存在于开局（第一次拾取之前）。空手类谜题本质是开局顺序谜题。
- 推论 5（提取槽）：每次进攻的提取槽 = 当前开口方向那条臂（轴臂），开口在两条轴臂间交替 ⇒ 垂臂内容永不可提取；起始在**非开口侧**轴臂上的颜色每次进攻都被甩到新的非开口侧，同样永不可提取。每个中心「初始可提取的颜色」至多一种（开口臂上那枚）；其余只能靠玩家先投放再取出。

取舍记录：

- 离去基团去向：「落到攻击者身后」（v0 简化声明草图）→ 改为「**进攻击者手中**」。落点版必须定义墙 / 边界 / 中心 / 占用格的回退规则，规则重量大；换手版一句话可解释，且天然构成「取货—送货—换货」物流链。落点版（弹射）保留为后续「新规律」候选。
- 不加「主动丢弃」动作：动作空间保持四方向（solver 分支不膨胀）；丢弃用「走上另一基团格交换」表达，且判胜不关心手中物，丢弃无必要性。

### 关卡批次决策：《109.5°》01–10 教程批次（2026-08-23）

- 决策：手画 01–10 批次，**零引擎改动**。01–05 为教学段（背面进攻与空间站位），06–10 为多中心路线 / 顺序段。每关经 `pnpm solve chem level-XX` 验证，最短解长度断言进测试作为基线（同 §4 t3 批次的验证口径）。
- 教程形式：沿用 §4 的关卡 `hint` 字段决策（纯展示、shell 在棋盘外展示、只点拨不给答案）。教学段每关只教一件事：
  | 关 | 教什么 |
  | --- | --- |
  | 01 | 第一次撞入：朝开口方向撞，四臂翻转 |
  | 02 | 站到背面去：进攻方向 = 开口方向，先绕到对侧 |
  | 03 | 读开口方向：开口朝哪，从哪侧撞 |
  | 04 | 墙与绕行：直路被堵，先选绕行方案 |
  | 05 | 完整路线规划：把整条绕路想完再动手 |
  | 06 | 多中心：各看各的开口，规划顺路顺序 |
  | 07 | 顺序有代价：墙分隔棋盘，进攻顺序决定绕路长短 |
  | 08 | 克制：已达标中心别碰（碰一下就翻坏） |
  | 09 | 房间与门：跨房间进攻，先定顺序再找门 |
  | 10 | 综合毕业：三中心三开口，完整规划 |

### 关卡批次决策：《109.5°》11–15 搬运批次（2026-08-24，v1 复测批次）

- 决策：v1 基团搬运落地后，手画 11–15 五关构成「第 5 关测试」复测批次（对 t3 的既有 01–10 证据）。每关经 `pnpm solve` 验证，最短解长度断言进测试；`scripts/trace-chem.ts`（`pnpm trace:chem`）逐帧回放最短解用于「预期解 vs 实际最短解」比对。
- 教学序列（每关只教一件事；`hint` 只点拨不给答案）：

  | 关 | 教什么 | 最短解 |
  | --- | --- | --- |
  | 11 带上它 | 拾取场珠；携带撞入 ⇒ 装到正对你的臂，换出开口臂旧色 | 6 |
  | 12 取货 | 跨中心取送：空手撞是翻转，持珠撞才是交换（必须先有货才能换出货） | 11 |
  | 13 一手交一手 | 循环交换：A 缺的色在 B、B 缺的在 A，顺序只有一种能闭环 | 10 |
  | 14 两种目标 | 翻转目标 vs 搬运目标同关混用；空手一击只有开局一次机会（手持不变式） | 10 |
  | 15 毕业题：同一位，两扇门 | 共享站位（同一格向北/向南是两个进攻）+ 别碰已达标 + 一击必中的翻转目标 | 8 |

- 制关中确认的两条新不变式（手持不变式、提取槽，见 v1 规则推论 4/5）与两次关卡返工记录见 iteration.md #5——这是 v1 规则设计空间的第一手证据。

#### 染色教学返工（2026-08-23 试玩审查）

试玩表明 11–15 虽然在 `hint` 里写出了规则，但玩家到 19 关仍未形成稳定的交换模型。问题不在规则本身，而在教学只靠长句，且旧 Canvas 将普通臂画到相邻格中心——玩家站在进攻位时会盖住靠近自己的臂，恰好遮住新色珠的最终落点；整体旋转动画也没有提前说明「放入 / 换出」两条物流。

- 固定术语为 **「染色 = 交换 + 翻转」**，不再混用「装入 / 投放 / 取货 / 一手交一手」让玩家自行归纳。每次持珠进攻只记两个结果：手中色珠进入中心并随中心翻转；原开口臂色珠换到手中。
- 11–15 教学重新分工：11 只教一次完整染色；12 只教「换出颜色」；13 教手中始终有珠、连续交换；14 对比空手纯翻转与持珠染色；15 才做路线综合。18–19 的提示回指同一套术语，不再另造「换进」等表达。
- 含游离色珠的关卡在教学面板常驻两行规则备忘；玩家持珠站到合法进攻位时，棋盘用手持色光环与流向箭头**预览本次染色的最终落点**，让规则从文字变成可验证预测。
- 普通臂缩回中心格附近，目标圈跟随真实臂端；玩家、色珠与目标不再共用相邻格中心。该调整仅改变渲染几何，状态、进攻站位、关卡解和 solver 基线不变。

### v3 机制群：广撒网批次（2026-08-24 决策）

**背景**：v2 复测前的产品决策——把头脑风暴产出的机制按关卡曲线**全部落地体验**，宁可多做、试玩后再删（2026-08-24 与玩家的共同决定）。选择标准见头脑风暴存档（iteration #6 后续）：每条机制要么引入一条新定理，要么精准打破一条旧不变式。本轮刻意**不做**两条深水区机制：空臂消除（推翻目标系统）与手性棋盘（状态/渲染翻倍）——需要独立验证周期，定题后再评估。

七条机制（21–40 关分批教学）：

1. **光照格（打开口轴）**：关卡可声明 `lights: [pos]`。玩家**走入**光照格的一瞬，**所有中心**的开口沿 N→E→S→W→N 顺时针移到下一条当前实际存在的臂；四臂中心等价于转 90°，三臂中心会跳过当前缺失槽（见 7）。只转开口、不动臂色、不消耗额外回合（就是那一步移动）。**打破开口轴不变式**——01–20 的最强结构定理从此不再绝对。设计用「全局生效」而非逐格指定目标：规则一句话可懂，代价是多中心关卡里每次照光都牵一发动全身（这正是谜题）。
2. **回收格（打破手持不变式）**：`disposals: [pos]`。手持色珠走上回收格 ⇒ 色珠销毁、手变空。空手走上无效果。「空手翻转」从开局限定变成**可再生的中盘资源**。
3. **保护基与脱保护格**：中心可声明 `shielded: true`（渲染为防护罩）。被保护中心：进攻无效、**共振也传不进去**（链在罩前停下——保护基因此兼任「连锁闸门」）。`deprotections: [pos]`：首次走上脱保护格，全场保护**永久**解除（状态位，进 stateKey）。玩法 = 先干别的、最后解锁的次序规划。
4. **分步目标（反应中间体）**：关卡可声明 `stages: [{goals}...]` 替代 `goals`。按顺序逐段达成：当前段所有目标同时满足 ⇒ 进入下一段（一步可连进多段）；全部段完成 = 胜利。`stage` 进 stateKey（它影响转移，不是纯计数器）。旧关无 stages ⇒ 规约为单段，行为不变。渲染：当前段目标正常虚线圈，未来段目标以淡圈预告。
5. **弹射中心（离去基团落到棋盘）**：中心可声明 `ejects: true`。持珠进攻它：携带珠照常注入（手变空），被顶出的基团**不入手**，而是沿攻击反方向从玩家身后飞出，落到射线遇到的第一个障碍前一格（墙/中心/其他色珠/边界）；身后第一格就被堵 ⇒ 进攻无效。空手进攻仍是纯翻转。搬运关从「手持物流」升级为「弹道规划」。
6. **弹射台（远程取代）**：`launchers: [{pos, dir}]`。**手持**色珠走上弹射台 ⇒ 色珠沿 dir 直线飞出（手清空）：命中中心时，若方向恰为其开口 ⇒ 发生取代——色珠装入、被顶出的基团落回色珠**刚离开的格子**（交换远程发生，必然合法）并触发共振；方向不合 / 命中保护罩 ⇒ 色珠停在该中心前一格变游离珠；命中墙 ⇒ 停在墙前一格；飞出棋盘 ⇒ 停在最后一格。动作空间不变（仍是四方向移动）。
7. **三臂中心（缺一臂的四槽结构，v3.1）**：数据仍使用 `kind: 'trigonal'`，但不再引入 mod 3 语法。中心有 N/E/S/W 四个方向槽，其中恰好三槽有臂、一槽缺失；成功进攻与普通中心执行**完全相同的 180° 翻转**（N↔S、E↔W），所以三颗色珠、缺失槽与开口箭头一起转到对侧，撞两次必定恢复原构型。持珠取代也复用普通中心语义：提取开口臂色珠、手持珠装入该臂，再随整体翻转落到对侧；三臂数量始终不变。共振只通过当前真实存在的面对臂连接，因此移动的缺口能随翻转接通 / 断开链路。光照移动开口时跳过当前缺失槽，保证开口始终附着在真实臂上。玩家教学只需一句：「和普通中心一样翻转，只是少一条臂。」渲染使用三角中心核区分种类，但动画改为与普通中心一致的刚体半圈旋转。
8. **标准杆（非机制）**：关卡可选 `par`（设计最短解）。HUD 显示标准杆，胜利时按步数给 ★★★（≤par）/★★（≤par+3）/★。只读信息，不进引擎状态。

结构注记（后续制关的基石）：

- 「同时性目标」不需要引擎改动——现有判胜本来就是「同一回合末全部满足」；它是**关卡设计手法**：把两个目标构造成只能被同一次连锁同时点亮（37 关）。
- 光照格转的是**开口**不是臂色 ⇒ 它改变的是「谁能从哪里被进攻」与奇偶时序，不改变共振链的颜色通断——两类谜题正交，可叠加。
- 三臂中心不是第三套旋转语法，而是标准翻转作用在一个**部分结构**上：缺口本身成为模 2 状态，并能控制共振拓扑。它不同于「空臂消除」：臂与珠没有被玩家生成 / 销毁，中心始终恰好缺一条臂。
- 回收格 + 弹射中心互补：前者销毁、后者产出，场珠总量从此可增可减，11–20 的「颜色守恒」直觉失效。
- 保护罩是**唯一能挡住共振**的东西 ⇒ 「链闸」是 36 关起的新元件。

关卡批次安排（教学序列细化见批次表，入库时补数字）：21–25 单机制教学（光 / 回收 / 光×链 / 分步 / 三臂）；26–30 二段组合 + 毕业；31–35 弹射 / 弹射台 / 保护基教学；36–40 深度组合 + 大毕业。

#### 阶段护罩（保护罩 v2）

中心以 `shieldUntilStage: n` 一类数据声明「进入第 n 段时解除」。当前段 `< n` 时，护罩阻挡直接进攻与共振；上一段完成后，护罩在该回合所有取代 / 翻转 / 共振结算完毕后破裂，**不追溯放行刚结束的连锁**，从下一步起生效。解除是单向的，不再保留全局 `deprotected` 状态或脱保护地格。光照仍可改变罩内中心的开口——盾只隔绝撞击与共振，不冻结全局转轴。

护罩不能只做「完成 A，开放 B」的顺序门。入库关必须至少利用一种持续状态关系：第一阶段借盾保护未来目标不被误烧；开盾前预先配平邻接颜色 / 手持资源 / 罩内开口；开盾后共振图永久扩张；或多个护罩随阶段逐段打开形成链路扩展。未来段目标圈与护罩共享阶段编号 / 颜色，预演若将完成当前段，应同时显示护罩破裂，但不伪造同回合的追溯共振。

实现口径（2026-08-25，P0 已落地）：JSON 与运行态统一使用 0 基阈值 `shieldUntilStage`；例如 `1` 表示完成内部第 0 段、进入第 1 段后解除。阈值必须小于总段数，避免永远不会在可玩阶段解除的死护罩。关卡 schema 采用 strict object，旧 `shielded`、`disposals`、`deprotections`、`launchers` 会被显式拒绝，而不是静默忽略。`stateKey` 只保留会影响转移的 `stage`，不再存在全局脱保护位。

#### 三臂中心的空穴语义

三臂中心的缺槽正式视为开发者语义上的**空穴**，但它仍是「结构缺失」而不是第四色珠或可填充空臂：

1. 空穴没有颜色，不能被拾取、注入或填补；中心始终恰好三条臂。开口必须附着在真实臂上，光照移动开口时跳过空穴；光照本身不移动空穴。
2. 空穴不能参与共振。相邻中心只有在双方相对方向都存在真实臂且颜色相同时才连通；任一侧为空穴即没有键，也不存在「空色相等」。
3. 每次标准 180° 翻转都会把空穴移到对侧，因此空穴只有两个奇偶态。例如 N 空穴翻后变 S 空穴：它在南北两条支路之间构成一个两态换路器，而不是 mod 3 旋钮。
4. 共振进入三臂中心前看它**当前**是否有面对臂；若从别的方向成功传入，该中心先整体翻转，再以**翻转后的空穴位置**继续检查下一跳。由此一次连锁可以在该中心处改道或止住。
5. 空穴本身不能作为颜色目标；目标可以指向当前为空穴的方向，但含义是要求之后通过翻转让一条真实色臂进入该槽位。

围绕空穴优先开发四类题：① **断路器**——先以空穴截断危险链，翻转后才接通；② **保险丝**——连锁到达前把空穴翻向链尾，保护已达标中心；③ **双路换向**——N/S（或 E/W）两条支路只能有一侧具备真实臂，奇偶决定传播出口；④ **阶段拓扑**——第一段利用空穴保持断链，阶段护罩解除后再翻转空穴，把新增节点纳入第二段共振。光照只负责选择可进攻方向，空穴负责决定真实拓扑，两者分工必须在关卡中可被玩家分别预测。

**v4 新机制（2026-08-25 决策并实现；首批按旧编号 45–50 入库，定题后重排至 41–46）**：

**① 弹射打结构联动（`ejects` + 可选 `hitLights` / `hitCenters`）**：
- 弹射珠仍沿攻击反方向飞到射线最后空格；新增两种可选的“落地触发”：
  - `hitLights`：弹射珠落在光照格上时，落地的一瞬触发该光照（所有中心开口顺时针移到下一条真实臂），珠留在光照格上成为可拾取基团。
  - `hitCenters`：弹射珠被某中心挡住、且落点恰是该中心当前合法进攻位（中心开口的反面）时，珠“撞”该中心：中心做一次纯翻转，并继续沿共振链传播；若该中心带护罩 / 被再生护罩保护则不触发。光照触发先于中心撞入判定，因此同一落点可先转轴再撞入。
- 两个触发都只在弹射中心显式开启时生效，旧关零影响；渲染仍复用现有弹道 / 落点预览，中心撞入复用纯翻转 + 传播动画。

**② 护罩再生（`reactiveTo`）**：
- 在中心上声明 `reactiveTo: { center, arm, color }`，表示“这条反应中间产物臂被破坏时，护罩会回来”。规则：只要 `reactiveTo` 指向的臂当前颜色 ≠ 声明的颜色，该中心就处于护罩状态（阻挡进攻与共振）；当该臂恢复成声明颜色时，护罩立即消失。
- 与 `shieldUntilStage` 可叠加：先按阶段阈值打开，之后若中间产物被破坏，护罩会再次出现；修复中间产物则重新打开。护罩恢复是纯当前状态推导，不需要额外状态字段，`stateKey` 不膨胀。
- 设计意图：让“护罩”成为共轭传导的可控闸门——玩家可以选择先破坏中间体关闸、再修复放行，而不是只做一次永久解锁。该机制会增加回溯风险，只宜在后期少量使用。

**v4.1 护罩关返工（2026-08-25 已实现）**：

1. **常显因果而非只显结果**：再生罩打开时仍显示断开的休眠六边形与 `R` 徽标；受保护中心到 `reactiveTo` 指向臂之间常显一条对应颜色的控制线。关盾时线与罩增强，开盾时退为淡色。预演必须同时显示将要生成 / 消失的罩，不再把再生罩误当阶段编号动画。
2. **现 43「关闸保形」只用一个最终目标**：开局罩是打开的；玩家必须主动破坏控制臂关盾，隔离一条会烧到已达标中心的共振支路，完成关键翻转后再修复控制臂。最终态重新开盾，但不得追溯传播。删除“先破坏、再修复”的阶段指令与剧透 hint，让关闭护罩第一次产生正收益。
3. **现 44「回授闸门」保留闭→开→闭→开的反馈拓扑**：控制臂与闸门相邻，第一次开门允许链进入闸门，链的回授又破坏控制臂并关门；第二次修复同时成为下一次点火。把控制臂、闸门和链尾的最终构型都列入同一目标，使玩家读的是完整回路而非只追链尾颜色。
4. **现 45「护罩缓冲」改为弹射碰撞的反用法**：开局罩打开，直接发射会撞翻已达标中心；正确做法是先关盾，让飞珠只落地而不撞核，取走弹出资源完成物流后再修复控制臂开盾。它验证“盾能阻挡 `hitCenters`”而不是再次做开锁题。

#### v6 步数预算（moveLimit）与空穴道岔（2026-08-28 决策）：第二批高难池 67–74

**背景输入**：协作者对 57–66 的三点反馈——① 弹射珠撞格子的机制还有很大空间，但既有关卡里「撞核 vs 走过去自己撞」总是可以互相替代；② 建议从某关之后给高难关加**总步数限制**；③ 三臂中心可以当「道岔」控制传导方向、护罩开合可以切断传导链，值得成组开发。

**结构性事实（本批设计的理论基石）**：在回合制、无时限的规则下，弹射撞核与玩家步行进攻**只差步数、不差可行性**——弹道线上的格子全部可行走，飞珠能落到的进攻位玩家一定能走到。因此「撞核不可替代」无法靠几何实现，只能靠预算把「绕远」变成「非法」。反之，三臂道岔存在真实的结构自由度：hole 在 N/S（或 E/W）时另一对方向的臂各有一条，翻转即出口换向；共振波**先翻后传**，故下游走向由「波后拓扑」决定；且键传导有奇偶锁——两端翻转次数必须同奇偶，玩家单独扳岔会断掉来路键，必须用「补一枪再同步」补偿。

**决策与理由**：

1. **引擎新增可选字段 `moveLimit`（总步数预算）**，缺省 = 无限制，01–66 全部不受影响。精确语义：
   - `moves >= moveLimit` 时**一切动作无效**（与撞墙同语义：状态不变、不消耗）；胜利条件不变。预算用尽未胜 = 卡死，靠撤销 / 重开恢复——引擎保持纯函数、无失败态。
   - 定义了 moveLimit 的关卡，`stateKey` 追加「剩余步数」；未定义的关卡 stateKey 逐字节不变（老关卡 solver 行为零变化）。
   - 设计口径（2026-08-28 协作者定量修订）：**两档红线**——零冗余关（69 / 70 / 71 / 74，命题本身是「预算使撞核不可替代」）`moveLimit = 最短解`；其余预算关统一 `moveLimit = 最短解 + 3`（三步容错：足够判死 ≥+4 的绕行，又不至于一步都不能错）。由测试按档锁定。
   - 剩余警示（协作者提案）：剩余步数 ≤ 3 且未胜时，棋盘四周亮红色警示框（`#budget-alarm`，`--tone-red` 描边 + 内外辉光），**每动一次跳一下**（脉冲动画重启，reduced-motion 降级为静态）；HUD「剩余」统计同步变红。
   - 理由：预算是通用收紧器——它同时守护撞核效率、光照格乒乓、护罩试探等一切低效动作；且让「等长捷径绕开」的约束搜索从「par 内无解」升级为「预算内无解」，证明力更强。
2. **空穴道岔（switchboard）命题族**：三臂中心作为传导分岔的转辙器，波从一口进、按波后拓扑从其它口出；多波次之间靠「谁当源、打几枪」控制路由；单扳岔会断来路（奇偶锁），需要补偿枪或借射。这族刻意不用新 schema，纯组合。
3. **第二批高难池 67–74，三族命题**：道岔教学（波反弹 / 串联岔）、红线（预算使撞核 / 双喷口 / 接力 / 光路经济不可替代）、汇流（道岔 × 预算 × 闸门 × 弹射的 capstone）。全部避开 57–66 已有命题与布局。同时给 57–66 统一补 `moveLimit`（协作者「高难关都有总步数限制」的落地），hint 追加一句「本关步数有红线」。
4. **已入库基线（2026-08-28 验证，同日按协作者定量修订为两档红线）**：67–74 依次 par 11 / 10 / 10 / 14 / 14 / 11 / 19 / 14；其中 69 / 70 / 71 / 74 红线 = par（零冗余，命题本身依赖预算），72 / 73 与 57–66 = par + 3。分档断言见 levels.test.ts；69 / 74 通过「预算内不存在绕开撞击的通关路径」约束搜索（证明力强于 par 内无解：是预算判非法，不是更长）；67 / 68 锁定波的实际换向轨迹（北口+东口双出、北→南回传、先西后北的奇偶锁）。开发中确认三条造关事实并沉淀进测试：x 轴镜像会翻转光照「顺时针」方向感（含三臂的关 par 会变甚至无解，因此镜像变体只用于纯 tetra 关，其余用 180° 旋转）；周期 2 + 键奇偶锁使「单独扳岔必断来路」，道岔只能靠波序或借射换向；玩家持珠无法空手进攻（无丢弃动作），接力路线上的「空手拍」结构性不存在。

### v2 新规律：共振传导（2026-08-24 决策）

**背景**：v1 复测反馈——搬运的空间深度成立，但仍缺「一击改变多个中心」的连锁爽感；玩家明确要求连锁反应、并希望更多借有机化学的意象。决策：把原排在 21–30 段的第一条「新规律」提前到 16–20 段，选用**共振传导**（共轭体系的抽象）。

规则：

1. 两中心正交相邻（曼哈顿距离 1）时，它们通过彼此面对的两条臂相连（渲染上画成键）。
2. 每当一个中心 X 被翻转（玩家进攻或共振传播所致），检查 X 的四邻：对每个**本次连锁中尚未翻转**的相邻中心 Y，若 X（翻转后）面对 Y 的臂色 == Y 面对 X 的臂色 ⇒ Y 自动翻转一次（**纯翻转**：180° 对换 + 开口反向），随后以 Y 为源继续传播。
3. 一次进攻引发的连锁中每个中心至多翻转一次（保证终止）；传播不触碰手持与场上色珠。
4. 传播顺序：队列 FIFO、邻居按 N/E/S/W 枚举。**结果与顺序无关**：每个中心至多翻一次且翻转是固定变换——顺序只影响观感（渲染按传播距离做阶梯动画）。
5. 完全向后兼容：01–15 无相邻中心，规则从不触发；动作空间、`stateKey`、solver 零变化。

化学映射：共轭 π 体系 / 共振传播——面对臂同色 = 共轭接通，一处反应（翻转）沿共轭链传导。

结构性质（制关基石）：

- 连锁判定用**翻转后**的颜色 ⇒ 链的接通状态随每次翻转重新计算，「多米诺式逐级接通」成为核心谜题元素（17 关）。
- **链环颜色不可投放定理**（16–20 制关中证明）：面对相邻中心的臂永远无法成为投放落点（投放站位被邻居中心占据）⇒ 玩家对点火的控制权只能是**翻转奇偶**，不能是颜色投放；「配平」类设计全部退化为奇偶设计，这是本规则下关卡深度的真实来源。
- **奇偶点火**：面对臂颜色在每次翻转时与对侧臂互换 ⇒ 链在奇/偶数次翻转间交替通断；同一中心连续进攻可依次点燃不同方向的链（20 关）。
- **回火**：被传导翻转的中心会以新颜色重新检查邻居 ⇒ 设计不当会让连锁弹回、摧毁已达成目标（20 关初版因此返工：需保证「翻转后的面对臂色 ∉ 邻居后续所有奇偶态」）。
- 夹在两个中心之间的链中间中心天然不可直接进攻（站位被邻居占据），只能被共振改变——「只能通过连锁到达的中心」是新的关卡元件。
- 共振是双刃剑：链尾若挂着已达标中心，错误的奇偶时序会把震动烧过去（19 关的负面用法）。

取舍：

- 消除（anti-periplanar）继续预留：需引入「空臂」概念，规则重量大；共振复用既有状态、零新概念，风险×收益更优。
- 「离去基团落点（弹射）」版本继续预留（见 v1 取舍）。

### v0 结构性上限：构型奇偶性（2026-08-23，制关中确认）

- 每次进攻都是同一个 180° 对换 ⇒ 每个中心只有「初始 / 翻转后」**两种构型**（周期 2）。
- 推论 1：某中心的目标要么恰好 1 次进攻可达（奇数次），要么初始已满足（偶数次 = 0 次，即「别碰它」）。「连续翻转达到目标朝向」在 v0 下**不存在**，§6 曲线 06–10 段改由路线长短、进攻顺序、「别碰已达标中心」提供深度。
- 推论 2：目标按奇偶构造 ⇒ 需要翻转的中心必然至少被撞一次，**背面进攻机制不可能被绕开**（天然满足 §7 的过滤标准）。
- 推论 3：连续翻转的组合空间只能由正式规则（基团搬运或新的翻转维度，见上方简化声明）解锁——这是「第 5 关测试」定题的关键输入之一。
- **2026-08-24 更新**：v1 基团搬运落地后，轴臂成为可任意注入颜色的插槽（见 v1 规则「轴臂 = 插槽，垂臂 = 奇偶锁」），本上限**只对垂臂目标继续成立**（且是刻意保留的设计维度，不是缺陷）。

## 7. AI 关卡 pipeline（评审重点）

目标：展示「AI 协作完成游戏设计」，而不只是 AI coding。

```
LLM 生成候选关卡 JSON
  ↓ zod 校验（结构/边界/重叠）
  ↓ Solver（BFS）验证有解 + 求最短解
  ↓ 过滤：过于简单 / 存在绕开核心机制的捷径 / 目标机制未被实际使用 / 解过长
  ↓ LLM 对有趣程度评分 + 与关卡设计意图比对
  ↓ 人工试玩
  → 最终关卡入库
```

迭代证据要留档（写进 `iteration.md`）：某关初版被 solver 发现绕开了目标机制 → 修改墙体 → 若干轮迭代后机制成为必选。这类「预期机制 vs 实际最短解」的对比是答辩时最有说服力的材料。

当前已具备：
- zod 校验（各游戏 `level.ts`）、通用 BFS solver（`src/core/solver.ts`）、命令行验证（`pnpm solve`）。
- 《109.5°》最短解走路税审计 `scripts/audit-chem.ts`（`pnpm audit:chem [level-XX ...]`）：自动区分有效交互 / 普通移动，输出决策密度与最长连续通勤，供批量筛出「解很长但决定很少」的关卡。
- 构造-验证工具 `scripts/craft-t3.ts`（`pnpm craft:t3 <spec.json>`）：从「预期解序列 + 起点 + 墙」正向构造关卡并用 solver 核对（对应上面流程的「生成 → zod 校验 → Solver 验证」三步）。
  人工设计关卡时也走这条路径，保证「预期解可行」与「最短解长度符合意图」都有机器证据。

尚缺：LLM 直接生成候选关卡、有趣程度评分标准、关卡批次管理工具。

## 8. 技术架构与关键决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 框架 | **无框架**（vanilla TS + Vite） | 回合制确定性谜题没有框架要解决的问题；时间紧，配置成本零收益 |
| 渲染 | Canvas 2D | 棋盘小、动画自由度高；DOM 方案亦可但补间/特效受限 |
| 引擎形态 | 纯函数 `step(state, action) → state`，状态不可变且完全可序列化 | 免费获得：撤销、重放、Node 侧 solver 复用（三者都依赖状态即数据） |
| 游戏接入方式 | 统一 `GameDefinition` 协议（parse / initial / actions / step / isWin / stateKey） | 双原型共用骨架；未来新机制原型接入成本极低；solver 与协议是同一份设计 |
| 关卡数据 | JSON + zod 加载期校验 | AI 生成的脏关卡在加载时报错，而不是渲染时崩溃 |
| 运行时依赖 | 仅 `zod` | 比赛风险控制 |
| `stateKey` 约定 | 唯一状态标识，**不含步数等纯计数器** | solver 去重与撤销判空都依赖它；含计数器会导致搜索无法剪枝 |
| 本地进度持久化 | `localStorage`，版本化 key `lexin.progress.v1` | 纯静态页无后端；只存已通关关卡 + 每个游戏最近打开的关卡，数据量小、同步读写足够；隐私模式 / 禁用 / 满配额时静默降级 |
| 通关反馈收集（构建期可选） | `VITE_FEEDBACK_ENDPOINT` 构建期开关；dev 默认开启指向 `http://127.0.0.1:8787` | 通关卡片附带难度 / 趣味 1–5 评分与可选快捷标签，并 POST 到自建 FastAPI 收集器；**默认构建不含任何联网行为**，比赛提交产物保持纯静态 |

### 可选数据反馈收集（2026-08-25 决策）

比赛硬约束「纯静态、无后端、无联网运行时依赖」**不变**：默认构建（不设环境变量）时反馈功能完全休眠——不渲染 UI、不发任何请求。但开发期与公网试玩需要低成本收集「难度 / 趣味」主观数据，故加一个构建期开关，与玩法、渲染、关卡零耦合：

- **开关**：`VITE_FEEDBACK_ENDPOINT`。dev（`vite dev`）默认开启并指向 `http://127.0.0.1:8787`；任意环境可用 `?fb=<url>` 查询参数临时覆盖（cloudflared 快速隧道地址每次重启都变，免重建调试）。
- **收集点**：通关卡片（overlay）显示难度 / 趣味各 1–5 分，两条都选才可提交；额外提供 `规则没看懂 / 卡在推理 / 操作不顺 / 走路太多 / 太简单 / 很有意思` 六个可多选快捷标签，不要求文字输入。星标保持等宽正方形，标题右侧只写“可选”，避免反馈区自身制造阅读负担。提交 POST `/api/feedback`（CORS 全开）。同关卡评分与标签按会话记忆，重开可一键复评；记录追加式，视为主观样本更新。
- **后端**：`server/app.py` 单文件 FastAPI，按固定白名单校验可选 `tags` 数组并追加写 JSONL（`server/data/feedback.jsonl`）；缺省 `tags` 为空以兼容旧客户端。`cloudflared tunnel --url http://127.0.0.1:8787` 暴露公网。理由：评分与结构化标签是低维度主观数据，不需要事务 / 账号 / 去重，JSONL + 统计脚本足够；后端不进前端产物，也不进提交。
- **纪律**：失败静默降级（面板提示可重试或忽略），不阻塞通关流程；评分与 `moves` / `par` 一并上报，便于后续按步数聚类分析难度感知偏差。

### 本地进度持久化（2026-08-25 决策）

之前 `completed`（已通关标记）与 `gameIndices`（各游戏最近打开的关卡）只存在内存里，刷新即丢。纯静态 H5 没有后端账号，最合适的是浏览器自带存储：

- **选 `localStorage` 而不是 `sessionStorage`**：`sessionStorage` 只活到标签页关闭，无法满足「刷新 / 重开浏览器后进度还在」；`localStorage` 按源持久保存，数据量小（几十个字符串），同步 API 足够。
- **选 `localStorage` 而不是 `IndexedDB`**：IndexedDB 适合大对象 / 频繁查询 / 离线资源，对本项目当前存档规模是过度工程；将来若要持久化整盘 `History`（含撤销栈）或大量标记，再升级不迟。
- **存储内容**：版本化 key `lexin.progress.v1`，保存 `{ completed: string[], current: Record<game, index> }`；`completed` 用 `game:levelId`，关卡重排比纯序号更稳。
- **写入时机**：通关时写入 `completed`；切换 / 打开关卡时写入当前关。数据变更频率低，不需要 debounce。
- **容错**：读取时 `try/catch` + 字段白名单清洗，损坏 JSON 回退空进度；写入失败（隐私模式 / 配额满）静默忽略，不阻塞游戏。
- **不做**：不持久化整盘 `History` / 未完成局面，保持存档协议最小；玩家标记仍按 §11 的「会话内」设计，本次不跨会话。

## 10. 命名与视觉包装方向

### 命名（已定）

| 原型 | 正式名 | 理由 |
| --- | --- | --- |
| t3 | **《t+3》** | 名字即规则：你按下的每个键，都会在 t+3 时刻再次生效。标题画面就是 `t + 3 [START]`，零解释成本；数字可随时间层扩展（+2 / +4 / +6）「长大」 |
| chem | **《109.5°》** | 四面体键角——只有懂化学的人才认得出的 nerd 符号，与《t+3》构成「符号双联」；游戏内不出现任何化学术语，标题是第一个揭晓点 |

命名原则：**短**（标题画面就是一行字）、**能当教学用**（名字 + 一句话就能懂）、**留彩蛋位**（第二层含义留给答辩揭晓）。

### 游戏内术语表与文案风格（2026-08-28 决策，试点阶段）

全量审读玩家可见文案（教程卡 / 56 关 hint / 规则书 / 棋盘内标签）后发现两类问题：

1. **文风带生成腔**：金句式收尾（「手变空本身就是资源」「每颗珠都有自己的去处」）、「不是 A，而是 B」对仗、「这就是 X」命名腔、「染色 = 交换 + 翻转」公式化、「先想清楚：」式说教冒号、三连排比——单独看每条都通顺，堆在一起就失去人味。
2. **术语膨胀**：约 15 个底层概念对应 60–70 种表面写法。仅「被顶出的那颗珠」就有 飞珠 / 离去珠 / 被顶出珠 / 余料 / 下一棒 / 货物 / 注入物 / 终投 八种叫法；「空穴 / 缺口」甚至在同一关的名字与 hint 里混用。另有化学词泄漏进玩家文案（「构型」「游离」），违反本节红线「游戏内不出现任何化学术语」。真人试玩反馈亦指出术语过多。

**决策一：术语定名表。** 每个概念只保留一个玩家可见词；新写或重写的玩家文案只允许使用定名：

| 概念 | 定名 | 淘汰说法 |
| --- | --- | --- |
| 中心 / 臂 / 开口 | 中心、臂、开口（首关教一次「白箭头 = 开口」对应） | 白箭头（首现外）、色臂、插槽 |
| 站位 | 进攻位 | 合法进攻位、进攻面、进攻轴、撞入位 |
| 翻转 | 翻转（首关说一次「整个中心转半圈」） | 纯翻转、空翻、翻面、换边、180° |
| 空手撞 | 空手撞 | 纯翻转、空翻 |
| 持珠撞 | 染色 | 取代、注入、投送、终投 |
| 交换结果 | 放入 / 换出（仅保留在交换预报面板，延续盲测协议约束） | 换货、输入 / 输出、注入物 |
| 共振 | 共振；亮 / 暗只作键的状态描述 | 震动、传导、点火、连锁传播 |
| 空穴 | 空穴（全游戏统一） | 缺口、虚线空槽 |

**决策二：文案风格红 / 黄 / 绿牌。**

- 红牌（禁用）：金句式收尾；「不是 A，而是 B」对仗；「这就是 X」；「A = B + C」公式；「先想清楚：」「出手前先预测：」式说教冒号；一句三并列；生造词。
- 黄牌（限量）：破折号每条 ≤1；反问每关 ≤1；每条 hint ≤2 句、约 40 字。
- 绿牌（鼓励）：口语动词（撞、转、捡、送、挡、飞）；直接祈使；具体名词（「弹出的珠」不写「余料」）。
- 关卡名目标语感沿用现有达标样板：「一撞，两座一起转」「碰不到的中心」「先碰哪一座」「从 A 送到 B」——一句口语或一个具体画面，不造词；名字不得直接宣布本关要由玩家推出的不变式。

**决策三：分两步执行。**

- 试点（#59 已落地）：重写最严重的 10 条 hint（level-04/05/10/11/25/39/46/49/50/55）、教程卡 5 处金句 / 泄漏词（「这就是染色」两处、「这就是预演：…构型」、「关门有时不是障碍…」「它不是一次性打开的门…」）；教程卡顶部英文眉题去设计行话：`MECHANIC REVEAL` → `NEW RULE`、`CORE INPUT` → `BASICS`（玩家不应看到「机制揭示」这类开发词汇，保留英文仪器面板感）。
- 全量（#60 已落地）：规则书 11 条、全部 56 条 hint、教程卡全部残留、34 个含淘汰术语 / 造词的关卡名（双态闸门→「一条臂，两扇门」、回授闸门→「撞完自己关门」、三响余料→「别急着停手」等；「一撞，两座一起转」类达标名保留）、选关面板章节标签与 Inspect 面板「构型周期」；`levels.test.ts` 已加「01–56 hint 不含淘汰术语」守护测试防回潮。同日并行入库的 57–66 制关批次不在本轮范围，其入库文案需按本节规则另行套用。

与既有决策的关系：§5 固定术语「染色 = 交换 + 翻转」的定义不变，但只作开发者口径；游戏内文案用句子呈现（放珠加翻转这一套叫染色），公式式表达不再出现。本决策不修改引擎规则、关卡结构、`stateKey` 或 solver，只改展示字段与 `hint` 文本；`hint` 继续遵守 §4「只点拨不给答案」（level-39 的 R 护罩规则陈述句按 #54 决策保留）。

### 视觉包装方向

比赛不要求故事与美术包装，但我们做**轻包装**：一切包装用排版、配色与程序化图形（Canvas）实现，零美术素材。

- 总体气质：极简 + 微科幻。等宽字体、深色底、细线条、克制的霓虹点缀；HUD 走「仪表」风格（步数、回声队列、开口方向等以读数形式呈现）。
- **字体与面板语法（2026-08-25）**：中文标题 / 正文统一使用系统中文无衬线栈，数字开启等宽数字特性；仅英文眉题与纯数据读数使用技术字体栈，避免中文被西文字体拆散回退或浏览器伪粗。面板减少大圆角，统一用紧凑圆角、切角读数牌、顶部信号线与低亮网格，形成“结构分析仪”而非通用网页卡片的观感。
- **玩法标记的可读性纪律（2026-08-24 试玩反馈）**：抽象的白色圆圈会被误读为渲染 bug——玩法标记必须自带方向/语义（开口用「朝外的白色箭头」、达标用「锁定圈 + ✓ 徽标」）。新增玩法标记时先问：不看文档能猜出含义吗？
- **《t+3》偏科幻 / 时间感**：时间线 / 刻度元素，回声以半透明「残影」+ 轨迹呈现，输入队列显示得像指令缓冲区。
- **《109.5°》偏化学味**：中心画成分子骨架风格（键线 + 原子点），背景可出现极低透明度的四面体线框，HUD 点缀刻度般的实验仪器感；**全程仍不出现化学式文字**。
- 标题画面：大字（`t + 3` / `109.5°`）+ 极简程序化动效（残影缓慢回放 / 四面体缓慢旋转），几十行 Canvas 即可。
- 纪律：包装不得干扰谜题可读性——装饰元素不许压棋盘；正式界面固定使用克制的默认装饰，不再用一个低价值开关占据顶栏。

### 《109.5°》界面与交互收敛（2026-08-23 审查决策）

本轮只调整壳层信息架构、输入方式与 Canvas 表意，**不修改引擎规则、状态转移或关卡数据**。审查发现旧界面沿用双原型开发工作台布局：游戏切换、关卡导航、步数、提示、装饰、撤销、重开在同一条窄顶栏竞争；Canvas 底部又重复显示步数并塞入手持 / 开口 / 标准杆 / 段数长句，在窄屏上会被裁切；移动端则没有可见的方向输入。

- **信息只出现一次**：Canvas 专注棋盘与即时反馈；关卡名、进度、步数、标准杆、分段进度与手持状态由 DOM HUD 承担，避免重复读数和 Canvas 文本裁切。
- **固定四层层级**：品牌 / 原型切换 → 关卡标题与进度 → 教学目标 → 棋盘与主操作。提示、撤销、重开是次级动作；不再显示装饰开关。
- **桌面与触屏输入同权**：键盘保留方向键 / WASD；棋盘下方提供拇指可达的四向键，Canvas 支持明确方向的滑动。所有按钮提供可访问名称、焦点态与至少 44px 的触控命中区；窄屏辅助按钮可隐藏视觉文字、只保留图标，桌面仍显示文字。
- **状态反馈靠形状 + 颜色共同编码**：玩家、游离珠、目标环与开口使用不同轮廓；色珠增加不依赖颜色的内部纹样，降低红绿辨识压力。无效输入继续使用位移抖动 + 撞面红闪，不新增文字打断。
- **响应式纪律**：宽屏保持紧凑仪器面板感，窄屏改为单列；棋盘始终是最大视觉主体，教学文案与控制区不得挤压或覆盖关键玩法信息。
- **单视口舞台（2026-08-25）**：正常游戏页固定在 `100dvh` 内，不产生页面级横向或纵向滚动；仅选关面板的关卡列表允许内部滚动。外围 Canvas 不再强制正方形：宽度铺满主栏，高度占用其余 UI 留下的空间；渲染器据实际宽高重新居中等比例格子，压缩的是棋盘上下留白而不是圆形、格子或文字。Canvas 绘制、点按命中和教程锚点必须共享同一动态逻辑尺寸，避免 CSS 拉伸造成图形与交互错位。
- **可思考性优先**：交互收敛的判据不止「信息只出现一次」，更在于「玩家是否需要用脑力维护游戏本可替他显示的状态」——见 §11 认知外置（自动显示 / 一步预演 / 轻量标记）。

### 对象绑定的新手机制揭示（2026-08-25 决策）

真人门槛要求玩家在第 5 关后能主动说清「放入什么 / 换出什么」，但原界面只有棋盘外的静态 `hint`；即使把它改成状态驱动文字，玩家仍要自己把说明映射回棋盘上的对象。决定把新手教学升级为**对象绑定、非阻塞的棋盘教练层**：聚光圈直接对准正在解释的玩家 / 色珠 / 中心 / 特殊格，小卡片与手势动画贴近对象但不拦截滑动，玩家一做出动作就由真实状态推进下一拍。

- 01 改为两拍：先用循环手指轨迹教手机玩家在棋盘上滑动到固定进攻位；到位后聚光四元中心，解释「四条色臂、白箭头、从背面沿箭头撞入、整体翻转」，再以第二段手势引导真实撞击。这里允许最短解从 1 调整为 2，因为第一步承担的是输入学习，而非走路税。
- 03 先聚光游离色珠，拾取并站到进攻位后不直接展示答案，而是先教一次**按住 / 拖住不松手**：键盘提示按住对应 W/A/S/D，触屏提示沿目标方向拖住；进入预演后，真实棋盘 ghost 与教练卡同步揭示“手中珠进入开口、随中心翻到对面”的彩色流向，并说明松开执行、回到原位或按 Esc 取消。预演教学保持非阻塞，快速点按仍按统一输入规则直接执行。04–05 再在合法进攻位并排显示**放入**与**换出**两条预测，使动作、动画、手持读数三者同屏对应。02 的撞错面 / 墙 / 边界继续提供原因反馈。
- 后续机制首次出现时复用同一视觉语法：10 共振键、16 光照格、17 分步目标、21 三臂空穴、27 弹射中心、33 阶段护罩、41 飞珠撞结构、43 再生护罩。首次揭示只说明对象和因果，不给多步路线；玩家开始行动后自动让位，静态 `hint` 仍可展开复习。
- 第一关不按“手机 / 电脑”或视口宽高比硬分设备，而按**当前输入方式**差分教学：首屏仅以主指针是否为 `pointer: coarse` 且 `navigator.maxTouchPoints > 0` 保守预判触屏，其余先显示 WASD / 方向键；收到真实 `PointerEvent.pointerType`（touch / pen / mouse）或方向键事件后立即覆盖预判。触屏版显示手指滑动轨迹，键盘版在同一棋盘锚点显示对应的 W/A/S/D 按键动画与文案。屏幕尺寸只负责响应式排版；UA / `userAgentData.mobile` 不表示玩家此刻使用的输入，也不作为教程分支依据。
- 引导只读取当前 `ChemState`、行动深度与关卡中已经声明的对象，不调用 solver、不复制引擎分支；交换预报由当前手持色、开口臂原色、翻转后的落臂实时推导。无效输入仍由 Canvas 抖动 / 红闪承担即时反馈，教练层只补充短句解释。
- 染色的通用规则只在 03–05 的对象绑定教程中建立，不再因为关卡含游离珠就在每一关的折叠提示中常驻重复；“本关提示”只展示该关 JSON 自己的 `hint`，让后期提示继续承担本关特有的观察重点。
- 教练层使用 DOM/CSS 程序化手势和聚光，不引入素材或依赖；说明卡必须可由玩家收起，收起后只隐藏大段文字与交换预报，在原卡片边缘保留小型 `TIP` 恢复按钮，同时继续显示聚光、滑动 / 按键指引与方向键高亮。这样小屏能看清棋盘，但不会丢掉“当前看哪里、怎样操作”的新手引导。除收起 / 恢复按钮外仍为 `pointer-events: none`，不得遮断棋盘操作。页面最底部保留轻量署名链接，不进入主操作层级。
- **第一关五拍指物（2026-08-26）**：01 在真实移动前用点击 / 轻触依次聚光五项信息：① 玩家白色光环「这是你」；② 绿色虚线目标圈「这里需要同色珠」；③ 南侧绿色珠「要把它送进目标圈」；④ 核内白箭头「站到反面并沿箭头方向撞入」；⑤ 才显示 WASD / 方向键或滑动手势并开放移动。到达进攻位后再确认有效撞击会让中心与全部色臂整体翻转 180°。前四拍只建立对象与因果，方向输入只推进讲解、不提前改变局面；教学不能把目标、身份、站位、输入同时塞进第一张卡。
- **第三关七拍染色流向（2026-08-26）**：03 同样先指物、后操作：① 聚光游离紫珠；② 聚光紫色虚线目标圈；③ 开放一步移动并拾珠；④ 聚光玩家右上角的手持紫珠并对应状态栏「手持」；⑤ 聚光核内白箭头，说明持珠撞入时紫珠先进入箭头开口；⑥ 聚光对侧紫色目标圈，说明整体翻转后紫珠落在这里；⑦ 才开放按住 / 拖住预演与松手执行。拾珠前两拍与拾珠后三拍只推进教学、不改变局面。03 仍只教“放入”单向流动，开口原珠“换出”留给 04，避免一关同时建立两条物流。
- **后续机制统一为“对象 → 条件 → 结果 → 操作”（2026-08-26）**：04 / 10 / 16 / 17 / 21 / 27 / 33 / 41–43 的首次揭示不再用一张总览卡。04 在拾珠后分别聚光“将换出的开口原珠”和“将放入的手持珠”，最后才显示双行交换预报；其余各段先以 2–4 个只读点击拍分别聚光机制对象及其关键关系（共振暗 / 亮键、光照格与开口、当前 / 未来目标、三臂核与空穴、弹射核 / 离去珠 / 落点、阶段编号与开放时序、飞珠撞核的进攻位、飞珠先触光再撞核的结算顺序、R 罩与控制臂），最后一拍才给当前局面真实可执行的方向或恢复自由操作。教学拍不调用 solver，只从关卡已声明对象和当前状态计算坐标；它可以解释本关用于教学的单步因果，但不得泄露后续多步路线。壳层是否拦截输入由当前 `TutorialModel.advanceOnTap` 决定，不再维护关卡编号 / 拍数的第二份硬编码表。
- **常驻规则手册（2026-08-26）**：方向控制区右侧增加低层级「规则」按钮，打开可滚动模态页；按正式曲线顺序收录目标与进攻、持珠交换、共振、光照、分步目标、三臂空穴、弹射中心、阶段护罩、弹射撞结构、再生护罩以及操作快捷键。手册用于随时复习，不替代首次出现时的对象绑定教学；条目只解释稳定因果，不给具体关卡解法。弹窗支持按钮、背景点击与 Esc 关闭，并保留明确标题与可访问性标注。
- **教程总开关（2026-08-26，v5.1 收紧）**：在行动 / 标准 / 目标 / 手持同层状态栏末端放置紧凑 `教程 开 / 关` switch，并把选择持久化到本地。关闭后隐藏 01–04 核心对象教学与所有后续机制首次揭示，且不拦截方向输入；05 起本就不再提供状态驱动解题路线。关卡自己的折叠 `hint` 与常驻规则手册仍保留，避免“不要自动教学”被误解为“删除帮助”。重新开启时从当前局面的相应教学拍继续；重开 / 重新进入 01 会从第一拍开始。

### 因果动画与双节奏（2026-08-27 决策）

真人反馈表明，关闭或跳过文字教程的玩家会把持珠取代理解成“中心对面的珠突然变色”：规则状态虽然正确，但旧实现会立即切到动作后手持状态，并在 260ms 内完成整核翻转；开口原珠离开、手持珠进入与随后翻转缺少可追踪的身份连续性。这个问题属于规则反馈，不应继续靠加长教程文案补救。

- chem 独立提供持久化的双档动画节奏，与 `教程 开 / 关` 完全解耦。玩家界面按熟悉的速度开关显示为默认 **`1×`** 与可开启的 **`2×`**；内部 `clear / fast` 只作为实现命名。1× 保留完整因果分镜，不喜欢文字的玩家可以关闭教程而继续从动画学习；2× 供已掌握规则的玩家压缩等待。
- 两种节奏复用同一套语义顺序，只改变停顿与重叠程度：**撞击确认 → 开口原珠与手持珠交换轨迹 → 整体翻转 180° → 共振逐核传播 → 弹射 / 护罩等结算反馈**。清晰模式在动画结束前不接受新的方向动作，避免后一步状态覆盖前一步因果；撤销、重开、换关仍可立即打断。
- “步进”按规则事件而不是按角度切分。标准进攻始终是一次完整 180° 翻转；动画可经过 90°，但不得在中点停成貌似可操作的合法构型，避免与光照的真实 90° 转轴混淆。
- 持珠取代必须画出双向身份轨迹：开口原珠去往玩家、手持珠去往开口；交换完成后，新珠才随整个骨架转到对侧。清晰共振的下一级必须等待上一级翻转落定，快速节奏才允许相邻动画重叠。
- 动画仍是渲染层私有时间线，不进入 `stateKey`、solver 或关卡 JSON；v5.3 起，普通移动仍可读取相邻坐标补间，但翻转源头与共振 / 弹射传播顺序必须消费引擎的一次性因果事件，不能再从两个 `ChemState` 的最终差异猜测。切换节奏只清空当前视觉时间线，不改变游戏状态。

#### 双节奏跟进：输入缓冲与再生盾因果时钟（2026-08-27）

- **1× 不丢操作**：清晰动画期间仍不允许下一动作提前改变引擎状态，但不得直接丢弃玩家已经完成的第二次按键。壳层保留一个“下一动作”缓冲槽；动画中收到方向输入就覆盖为最新方向，当前语义时间线结束后自动执行一次。撤销、重开、换关、切换倍速会清空缓冲，避免旧意图穿越局面。只缓存一步，不把回合制谜题变成不可撤回的长指令队列。
- **再生盾按控制臂结算，不按全动作收尾**：`reactiveTo` 护罩由某条控制臂实时决定。控制臂翻转落定时，R 盾立即进入生成 / 释放反馈；若本次释放让共振得以进入受保护中心，则清晰模式先完整呈现开盾，再保留约 180ms 的因果停顿，才让该中心及其后续链开始翻转。阶段护罩仍遵守“整次连锁后解除”的旧规则，二者不得共用同一个 `actionEndsAt`。
- **紧凑状态按钮**：动画倍速、教程与主题使用同一套无滑块两态按钮，关闭时低亮、开启时使用信号色点亮。动画按钮的“开启”专指 2×，关闭即默认 1×；教程按钮的开启 / 关闭保持原语义。宽屏三项并排在状态栏右侧，窄屏整组换到第二行，不让单个按钮与行动 / 持有等玩法状态争宽度。

#### 自动明暗主题（2026-08-27）

页面壳层首次进入时跟随 `prefers-color-scheme` 自动选择深色 / 浅色；状态栏同时提供“暗色模式”开关，玩家手动切换后把明确的 `dark / light` 偏好写入 localStorage，后续优先使用手动选择。DOM 与 chem Canvas 共用同一主题状态，但 Canvas 不读取散落的 CSS 色值，也不使用 `filter` / 整体反色：渲染层维护深浅两套**语义调色板**，按“画布底色 / 棋盘底板 / 网格 / 墙 / 键线 / 主墨色 / 面板 / 预演遮罩 / 危险反馈 / 五种玩法色 / 阶段色”等角色取色。浅色玩法色独立校准明度与饱和度，目标圈、原子、护罩和共振高亮再由深色轮廓 / 纹样维持边界；颜色身份继续由既有纹样双编码兜底。主题切换只更新渲染调色板、清空瞬时动画并重绘，不进入引擎状态、`stateKey` 或关卡数据。

#### 开局闭环：先演示因果，再让玩家触发亮点（2026-08-27）

- 第一关不再用“自己 / 目标 / 色珠 / 箭头”四次静态聚光逐物点名。开场只播放一次色珠绕中心半圈进入同色目标的循环演示，用一句话建立“正确碰撞会让整核翻转”；随后立即让玩家移动并亲手撞一次。静态聚光保留给后续真正需要辨认的新物件，不把闪烁本身当作规则演示。
- 所有有效直接进攻都必须有接触反馈，不能从玩家静止直接跳到中心旋转：玩家向中心短促前冲，在接触点出现冲击环 / 短射线，再回到进攻位；之后才进入交换或翻转。无效进攻继续使用红闪与抖动，两者在颜色、时序和结果上明确区分。
- 核心物流仍在 03–05 教会拾珠、放入、换出和跨中心运输；第 06 关把“换出蓝珠再送货”与一次双中心共振连锁合在同一张小图中，提前展示“一撞带动多个结构”的趣味点。第 10 关继续承担共振的正式逐物教学与预测巩固，因此早期展示不会替代后续规则解释。
- 浅色 Canvas 从“保证对比度而整体压暗”改为“干净底板 + 中高明度饱和玩法色 + 深色轮廓 / 纹样兜底”。浅色的黄 / 绿 / 盾阶段色不得退成褐灰；棋盘底、网格和墙减少灰色叠加，结构线可低饱和但玩法对象保持清亮。可读性由轮廓与纹样共同保证，不要求所有填充色单独满足正文文字的对比度标准。

#### v5.2 首关认知闭环回调（2026-08-28 决策）

**新试玩信号**：把第一关压成“半圈演示 → 立即操作”后，未接触游戏的玩家仍会先问“这个游戏是要干什么”。这说明演示能表现一次动作结果，却没有稳定建立玩家身份、胜利条件和棋盘符号之间的对应。这里缺的是核心规则教学，不是应当留给玩家发现的解题思路；因此不受 v5.1“05 起不代替玩家解题”的收紧影响。

- **恢复第一关五拍对象绑定**：真实移动前依次聚光 ① 白色玩家；② 绿色虚线目标圈，并明确“所有目标同色即过关”；③ 当前位于南侧的绿色珠，建立“珠 → 同色圈”的关系；④ 核内白箭头，说明从反面沿箭头撞入；⑤ 才按实际输入方式显示 WASD / 方向键或滑动手势并开放移动。到达进攻位后仍停留在第 ⑤ 拍，用真实撞击完成“整体翻转半圈”的闭环，不新增第六个概念页。
- **教程边界不变**：五拍只解释全局胜利条件、玩家身份、目标 / 色珠 / 开口四个核心视觉符号和基础输入，不给 05 以后任何取珠颜色、中心顺序或多步路线。第一关本身是固定的一次规则演示，不承担益智发现。
- **玩家移动必须有连续位移**：引擎状态仍即时落到新格，Canvas 只在渲染层从上一格向新格做短补间；动画不进入 `stateKey`、solver 或关卡 JSON。现有补间接入因首次设值把起点误置为终点而退化成瞬移，修复时必须显式提供上一格作为起点，并用单元测试守护起点、中间值和终点。

#### v5.3 因果事件轨迹（2026-08-28 决策）

**问题证据**：74《转辙·终章》中，玩家站在一格上同时邻接“右侧直接进攻中心”和“下方被共振带动中心”。旧渲染器只收到动作前 / 后两个 `ChemState`，先收集最终发生变化的中心，再把“数组中第一个与玩家相邻的变化中心”猜成根节点，并按几何相邻重新 BFS。该局面因此把下方中心误认成源头，动画顺序与引擎真实的“右 → 下 → 下一层分支”相反。更一般地，最终差值无法表示同一中心在一步内被不同波次翻两次，也无法证明传播经过了哪条当时亮起的键。

- **引擎是因果轨迹的唯一来源**：chem 新增纯函数结算入口 `resolveChemStep(state, action)`，一次返回 `{ state, events }`。普通 `step` 只返回同一次结算的 `state`，继续满足 `GameDefinition`、solver 与测试协议；不得在渲染层再次实现规则或从最终差值反推过程。
- **翻转事件记录真实传播边**：每次直接进攻、共振传导与弹射撞核都产生 `flip` 事件，至少包含中心下标、来源中心、波次、传播深度及该次翻转前 / 后的中心快照；直接进攻另记录手持注入 / 开口珠换出，弹射另记录真实路径与受撞中心。分支中同深度事件允许同时播放，不同深度必须保持父事件先于子事件。
- **轨迹不污染谜题状态**：事件只作为一次 UI transition 交给 Canvas，绝不进入 `ChemState`、`stateKey`、关卡 JSON、撤销历史或 solver 去重键；撤销、重开、换关清空未播完轨迹。预演仍直接展示一步后的 ghost，不启动正式事件时间线。
- **删除猜序兜底**：正式交互若没有匹配的 transition，渲染器应把它当作重开 / 撤销式状态跳变并重置动画，不再用“变化中心 + 几何距离”生成看似合理但因果可能错误的动画。74 的回归测试必须锁定直接源 `center 2`、下一层 `center 1`、再下一层 `center 0 / 3`；快速模式可以缩短间隔，但不得颠倒层级。

### 玩家辅助：solver 提示（2026-08-24 决策）

试玩反馈：部分关卡卡死后没有出路，玩家做不出来。决策：**提示直接复用通用 solver**，不写手打攻略。

- 壳层「下一步提示」按钮（H 键）：从**当前局面**跑一次通用 BFS（`core/solver.ts` 新增 `solveFrom(def, state, opts)`，引擎零改动），取解的第一步，以「下一步：→（向右）」的浮层展示；每次按都从最新局面重新求解，可以一步步连着要提示。
- 三种结果三句话：可解 → 给下一步；**不可解**（如回收格扔掉了必需的珠子、t+3 把队列搅死）→ 明说「这个局面走不通了，撤销 (Z) 或重开 (R)」——死局检测本身就是教学；求解被截断 → 退回展示本关文字提示。
- 为什么不做多级提示（先暗示再给答案）：时间紧，solver 方案一步到位、对两个游戏通用、零维护成本；玩家想自己憋可以不用它。提示不消耗任何东西、不计入任何评价（星级只看步数与标准杆），鼓励卡住就用。
- 成本上限：提示的 BFS 从当前局面出发，剩余深度 ≤ 通关深度；沿用 `maxDepth 30 / maxVisits 500k`，单关实测毫秒到百毫秒级，同步执行可接受（不做 Web Worker，避免过度工程）。

## 11. 认知外置：可思考性设计（2026-08-24 决策）

### 设计原则

> **Challenge reasoning, not memory.**
> 玩家的脑力应该用来发现规律和作出决策，而不是维护游戏本可以替他显示的状态。

诊断：试玩反馈「我知道要干什么，但我懒得一直在脑子里维护这个模型」不是零散 UX 小毛病，而是**两个候选机制都缺一层「可思考性设计」**。由此把「玩家是在花脑力推理，还是在花脑力记忆自己刚才推理出了什么？」确立为与机制深度并列的评判维度，并作为定题（§3）的正式输入。

### 机制分类与各自的外置难度

- 扫雷 / 数独类是 constraint deduction puzzle（推导格子的可能集），缺的是「命题记录」UI；
- `t+3` 与《109.5°》是 **state-transition puzzle**（S --动作--> S'），真正的负担是**计划序列的工作记忆**：「我刚才顺序想到哪了」。
- 二者外置难度结构性不同：
  - `t+3` 的认知状态是**一维输入时间线**——天然适合直接画出来。时间线一摆，记忆负担基本消失。
  - 《109.5°》的认知状态是**图**（手持 / 开口 / 目标 / 共振邻接 / 路线相互纠缠），语义密度高，外置 UI 天生更贵。
- 由此确立定题的补充判据：**同样深度下，一个机制需要多少 UI 才能让玩家舒服地思考？** 原创性优势（chem）要和这份认知复杂度一起称重。

### 三层认知外置（两游戏共同的 UX 准则）

| 层 | 内容 | 实现方式 |
| --- | --- | --- |
| ① 已能由当前状态确定的信息 | **自动显示，不要让玩家记** | t3：时间线 / 每枚回声下一步动作；chem：开口箭头、共轭键、达标 ✓、手持读数（既有）+ Inspect 面板 |
| ② 「如果我这么做会怎样」 | **按住预演，不逼玩家脑内模拟** | hold-to-preview：一步 Action Preview（`S' = step(S, a)` 的 ghost 可视化），机械展开交给游戏，策略选择留给玩家 |
| ③ 「我打算之后这么做」 | **允许玩家留下轻量标记** | chem：中心顺序标 ①–⑤，任意格 ★/？/×（游戏不解释标记含义，只提供外部工作记忆） |

预演**只做一步**（有界前瞻）：它替玩家计算 `step(S,a)`，不替玩家解 `a₁…aₙ`——不降低谜题含金量。

### 各游戏落地（本轮实现）

**`t+3`：时间线从视觉包装升级为核心玩法 UI。**

- 棋盘下方常驻**指令缓冲区网格**：列 = 未来回合 `t+1 … t+D+1`（D = 最长延迟；最后一列 = 你下一次按键将落入的位置），行 = 每枚回声（含延迟标签 `+d`）+ 玩家行。回声行已确定的拍显示彩色方向箭头，未输入的拍显示「·」；`t+1` 列高亮（下一拍）。
- 一句话规则升级为：**「输入不会消失，它会沿时间线向后流动。」**（level-01 hint 同步改写）
- 棋盘上每枚回声旁挂**下一步动作 chip**（已知才显示）——「红棋下一拍走 ↑」一眼可读。
- 按住方向键 / 拖拽棋盘：ghost 棋子（玩家 + 各回声的下一拍位置）+ 时间线上该输入将流入每枚回声的落点列。t3 **不加**标记系统：它的工作记忆就是输入缓冲区，时间线已完整外置，再加标记只是噪音。

**《109.5°》：Inspect / 预演 / 标记三件套。**

- **Inspect**：点按任意中心（不消耗回合）→ 面板并排显示该中心的**完整模 2 构型周期**（现在 / 翻一次后），当前态高亮；三臂中心同时显示缺口翻到对侧。回答「这个中心翻完是什么样 / 我是不是已经翻过它」——纯展示，读引擎导出的纯函数 `peekFlip`。
- **按住预演**：长按方向（或拖拽）→ 变化中的中心以 ghost 态显示**动作后的完整构型**（虚线晕圈标记「尚未发生」），共振链按传播距离标 ①②③；手持珠换出物、场上珠增减、目标 ✓ 锁定圈都按预演后的状态判定。弹射台 / 光照格 / 回收格等特殊格同样覆盖（预演 = 直接对 `step` 求值，规则零特判）。
- **标记**：M 键或「标记」按钮进入标记模式，点按中心循环 ①→②→③→④→⑤→清除；点按其他格循环 ★→？→×→清除。标记常显、只属于玩家（游戏不解释、不判读、不进引擎状态与 stateKey）；按「游戏:关卡」为键存会话内，撤销 / 重开不丢失。
- 撤销 / 重开 / solver 提示维持既有（历史栈 / Z、R、H）。

### 输入模型变更（两游戏统一）

- **tap = 执行，hold = 预演**：按下方向即计时，快速点按（≤ 阈值 280ms）在松开瞬间执行；按住超过阈值进入预演，**松开 = 执行**，键盘以 `Esc`、棋盘拖拽以回到原位、触屏方向键以移出按钮取消。提示文案不得在手机上只写 `Esc`；无法可靠区分手势来源的 Canvas 通用横幅并列显示“回到原位 / Esc 取消”。键盘换键滚动（按住 ↑ 时按 →）会先提交 ↑ 再预演 →；执行时机从 keydown 移到 keyup，回合制下无可感知延迟。
- 棋盘拖拽：位移 ≥24px 且主方向明确时先锁定动作方向；快速松手直接执行，不注入预演。只有方向锁定后继续停留 ≥280ms 才进入实时预演，变向会重置停留计时，松开执行；位移 <24px 视为点按（Inspect / 标记）。这样保留“拖住预演”的可发现性，同时消除普通快速滑动每步都压暗一帧的闪烁。触屏方向键用 pointer capture 保证「移开取消」语义。
- 实现依托：引擎本就是纯函数 `step(state, action) → state` 且状态可序列化——预演 = 壳层对当前局面求一次 `step` 后把 ghost 态交给渲染层，**不碰任何游戏规则**。

### 辅助分层配置（刻意不做的东西）

默认开启：① 全部当前事实自动显示；② 一步预演；③ 撤销 / 历史；④ 极简标记。按需开启：solver 提示（H，卡住才用，不计数不计星）。

**本轮不做 Plan/Sandbox 模式**（任意步数的沙盘模拟 + COMMIT/CLEAR）：无限撤销 + solver 下一步 + 一步预演已经给了相当的容错，再叠加任意长沙盘就是「游戏自己帮你玩」（预演退化为穷举试错），且实现预算留给定题后的正式版本。若试玩证明一步预演不足以支撑 5 步以上的规划，再评估受限版（例如最多预演 3 步且不显示达标结果）。

### 关卡设计审查原则（对 40–60 终盘、候选池与返工同样生效）

> 某一关的难点如果是「玩家必须记住 UI 本可以显示的状态」（8 步前对哪个中心做过什么、几拍前按了什么），那不是深度，是 UI 缺口——先问「是不是状态没表达清楚」，再考虑改关。

### 定题试玩实验（公平二选一）

给两个游戏各装上「认知外置版 UI」（本轮已做）后，各挑 **3 个非教学、真正需要规划的关**（t3：08/09/10；chem：18/19/20 或 28/36/40），找 3 位完全没接触过项目的人试玩。不问「好玩吗」，问四个具体问题：

| 问题 | 检测什么 |
| --- | --- |
| 有没有出现「我知道要干什么，但忘了刚才想到哪」？ | 工作记忆负担 |
| 有没有想拿纸笔？ | 最大红旗 |
| 输了以后你知道自己为什么输吗？ | 状态可解释性 |
| 你是在思考下一步，还是在计算系统下一步会发生什么？ | 推理 vs bookkeeping |

结论（连同 §5 制关证据与「同等深度的 UI 成本」判据）写入 iteration.md，作为定题依据。这比按现有代码量 / 机制数量选题公平得多。
