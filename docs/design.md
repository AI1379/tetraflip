> 本文档是项目设计层面的**单一事实来源**：机制定义、方案取舍、关卡曲线、AI 关卡 pipeline、架构决策都在这里。
> 任何玩法 / 规则 / 架构层面的决策变更，先改这里，再动代码（见 `AGENTS.md`）。
> 实现进度与时间线见 [iteration.md](./iteration.md)。

## 1. 比赛定位与总体策略

- 比赛窗口 2026-08-22 ～ 2026-08-31，产出纯 H5 小游戏，**关卡 ≥ 50**。
- 明确不做故事、不做美术包装——评审水分被砍掉，胜负手是机制本身。
- 评审对齐：玩法脑洞 / 50 关扩展能力 / H5 实现难度 / **AI 可参与程度**。
- 总体策略：
  - 找到「**10 秒能学会、50 关还没玩腻**」的机制，坚决不做大。
  - 技术上避开物理引擎、大量动画、联网、复杂 Roguelike；HTML/CSS/TS + Canvas，关卡全部 JSON 化。
  - 机制数量严格控制在 5 个左右，靠组合而不是靠堆新机关撑到 50 关。
  - 50 关不是 50 张不同地图，而是一条学习曲线：**教规则 → 理解规则 → 滥用规则 → 规则组合 → mastery**。
  - AI 参与不止于「AI 帮我写代码」，而是让 AI 进入**关卡工程 pipeline**（见 §7）——这是隐藏得分点。

## 2. 候选机制评估与淘汰记录

| 方案 | 一句话 | 结论 | 理由 |
| --- | --- | --- | --- |
| Echo Grid v1（延迟分身重放移动） | 过去的你沿路径复现移动，协作踩压力板 | **毙掉** | 与《星穹铁道》「黄金替罪羊」结构高度相似（延迟分身 + 重放输入 + 踩机关 + 到终点），近期且知名，评委认出即判「微创新不足」。加再多新机关也只会被理解为「黄金替罪羊 + 新机关」 |

| **《109.5°》（SN2 立体化学抽象）** | 背面进攻 + 构型翻转，把自然规律本身做成规则 | **候选 B（原型中）** | 题材与机制是同一个东西（同乐理游戏思路）；每十关「发现一条新自然规律」，作品统一性强 |

| Rule Shift | 每隔几关改变按键语义 | 备选 | 脑洞大，但很容易从「聪明」变成「烦」，关卡设计要求高 |
| One Line CPU | 3~5 指令槽循环执行的小机器人 | 备选 | 50 关容易、适合 AI 生成，但同类游戏多（Lightbot 等），原创性弱 |
| 不要同时发生 | 暂停/恢复周期运动物体，让多系统相位同步 | 备选 | 有冠军相、视觉极简，作为后备方向保留 |

**关键教训**：机制撞车检查必须前置。任何候选方案定稿前，先检索近两年的知名同类机制；「同一抽象原理」可以保留，「同一玩法结构 + 同一表现形式」必须砍掉。

## 4. t+3 规则定义（v0）

### 核心规则

> 你每次按下的方向键，会在未来某个延迟时刻**再次控制另一枚棋子**。

### 精确时序定义

- 第 `t` 回合玩家输入 `u_t`。
- 「当前」棋子立即执行 `u_t`。
- 延迟为 `d` 的回声棋子，在第 `t + d` 回合执行 `u_t`（每枚棋子有各自的 `d`）。
- 撞墙 / 撞出边界的移动：棋子原地不动，但**输入仍然消耗一回合**（回声队列照常推进）——这是刻意设计：被墙挡住的输入同样会进入未来的回声队列，是谜题的一部分。

### 胜负与局面

- 每枚棋子（当前 + 回声）各有一个目标格。
- **胜利 = 所有棋子同时位于各自目标格**（每回合结束后检查）。

### v0 已实现范围

5×5 棋盘；1 枚当前棋子 + 1 枚延迟 2 的红色回声棋子；墙；关卡 1（教学关，最短解 4 步）。

### 关卡格式决策：`hint` 教学字段（2026-08-23）

- 决策：关卡 JSON 增加可选 `hint: string` 字段（教学/点拨文案），由 shell 展示在棋盘外。
- 理由：新手教程不靠剧情与美术（比赛约束），只能靠「关卡顺序 + 极简文字点拨」。`hint` 是纯展示字段：不进引擎状态、不进 `stateKey`、不影响 solver，向后兼容（缺省即无提示）。
- 约束：`hint` 只写「点拨」不写「答案」——不直接给出解法序列，保护试错发现的空间。

### 关卡批次决策：01–10 教程批次（2026-08-23）

- 决策：先手工完成 01–10 教程批次（见 §6 细化表），全部经 `pnpm solve` 验证，且最短解长度需符合每关设计意图（断言进测试）。
- 引擎结论：**多回声、不同延迟不需要改引擎**——`echoes: T3EchoDef[]` 天然支持多枚不同延迟的回声棋子，复杂度完全由关卡数据承担。本批次零引擎改动。
- 工具决策：新增 `scripts/craft-t3.ts`（`pnpm craft:t3 <spec.json>`）：从「预期解序列」正向构造关卡（用真实引擎跑一遍序列，末位置即目标格），再自动跑 solver 核对可解性与最短解长度。这是 §7 pipeline「生成 → 校验」环节的第一块实现，供后续 40 关复用。

### 扩展路线（若 t3 胜出）

1. 多枚回声棋子，不同延迟（+2 / +4 / +6）——每次按键同时给多个时间层编程。
2. 回声瓦片：改变延迟、删除回声、旋转/镜像回声指令。
3. 压力板与门：回声可以替你踩板。
4. 棋子间碰撞规则（互斥 / 堆叠 / 推挤）——见开放问题。

### 开放问题

- 棋子之间的碰撞规则：v0 允许重叠，正式版需要定（重叠太宽松，互斥可能让回声规划更有趣）。
- 回声棋子被墙挡住时是否应有区别化的视觉/音效反馈。
- 是否需要「等待（空过一回合）」输入，以对齐时间层。

## 5. 《109.5°》（chem）规则定义（v0）

### 设计意图

**不做「有机化学游戏」，而是偷一个有机化学原理，伪装成纯游戏规则。** 全程不出现任何化学术语；玩家通过试错自己发现规律，玩到后面才意识到「这是立体化学」。这与此前乐理机制游戏的思路同源：题材与机制是同一个东西。标题《109.5°》（四面体键角）与化学味视觉是仅有的、被允许的泄露口（见 §10）；答辩时的揭晓时刻就是说破「你们玩的其实是 SN2 反应」。

### 化学映射表（仅开发者可见，不出现在游戏内）

| 化学原理 | 游戏规则抽象 |
| --- | --- |
| SN2 背面进攻（backside attack） | 只能从中心开口臂的正对面撞入；正面撞入无效 |
| Walden 构型翻转（inversion） | 撞入成功后中心四臂 180° 对调（N↔S、E↔W） |
| 离去基团方向 | 「开口臂」：攻击发生后翻转到对侧，决定下一次可进攻的方向 |
| 亲核试剂取代（Nu 进 / X 出） | 玩家手持基团撞入：装入正对攻击者的臂，开口臂基团换出到手中（v1，见下） |
| 共轭体系 / 共振传播 | 正交相邻且面对臂同色的中心连通：一处被翻转，震动沿连通链传导（v2，见下） |
| （后续）anti-periplanar 消除 | 预留：相邻两臂必须反向对齐才能触发消除 |
| （后续）环己烷 chair flip | 预留：FLIP 操作交换轴向/水平方向 |

### v0 规则

- 棋盘上有玩家（攻击者）与一个或多个「中心」。
- 中心有四个臂（N/E/S/W），各持一个颜色基团；其中一个臂是**开口臂**（可进攻方向的对侧标记）。
- 方向键移动玩家；玩家**撞向中心 = 尝试进攻**（玩家本身不进入中心格）。
- 进攻判定：玩家移动方向必须与开口臂方向**相同**（即从开口臂的背面一侧撞入）；否则进攻无效（不消耗回合）。
- 进攻成功：中心四臂 180° 对调（N↔S、E↔W），开口臂翻转到对侧；消耗一回合。
- 胜利 = 每个目标「某中心的某臂为某颜色」同时满足。

### v0 简化声明（重要）

v0 是**占位规则**，只用于验证协议与手感：进攻不携带/交换基团、离去基团不落到棋盘上、只有单一翻转操作。正式原型必须重新设计，候选方向：

- 攻击者从棋盘拾取游离基团，带入中心替换离去基团，离去基团弹落到攻击者身后——变成「基团搬运 + 立体化学」的空间规划游戏。
- 多中心联动、anti-periplanar 消除、环翻转等进阶规则按 §6 曲线逐步引入。

### v1 正式规则：基团搬运（2026-08-24 决策）

**背景**：01–10 批次的制关证据 + 试玩反馈确认 v0「进攻 = 纯翻转」的奇偶上限正是无聊根源——每中心仅 2 种构型，谜题退化为「路线 + 拨开关」，立体化学沦为贴皮。决策：按 v0 简化声明预留的方向，把进攻从「拨开关」升级为「**搬运 + 交换**」。

新规则（在 v0 基础上增量，**完全向后兼容**：不声明游离基团的旧关行为不变）：

1. 关卡可声明游离基团 `groups: [{pos, color}]`（可选，缺省空）。
2. 玩家走上游离基团格 = 拾取；手中已有基团则**交换**（手中基团落到该格，格上基团入手）。不新增按键，动作空间仍是四方向。
3. **空手进攻 = v0 行为**（纯 180° 翻转，不发生交换）。
4. **持基团进攻 = 取代 + 翻转**：进攻方向 d（= 开口臂方向，判定不变）；手中基团装到 **d 的对面臂**（即正对攻击者的那条臂，Walden 几何：进入者占据离去位的对面）；原 d 臂（开口臂）上的基团被顶入攻击者手中；四臂照常 180° 对调；开口臂翻到对侧。一句话教学：「你撞进去一个，撞出来一个。」
5. 胜利条件不变（目标臂颜色）；手中与场上基团不参与判胜。
6. 校验放宽：目标颜色只需存在于**本关任一中心臂或任一游离基团**中（原「必须在该中心四臂上」会禁止搬运关）。初始四臂互异约束保留；交换后允许同中心出现重复色。

关键结构性质（制关前推导、制关中确认，是 11 关起的设计基石）：

- **开口轴不变式**：开口臂只在自身轴上翻转（N↔S / E↔W），**轴永不变** ⇒ 每个中心永远只接受一个轴向的进攻。
- **轴臂 = 插槽，垂臂 = 奇偶锁**：持基团交换只发生在开口轴的两条臂上；垂直方向的两条臂只会彼此对调（v0 奇偶语义原样保留）。
- 推论 1：目标在垂臂 ⇒ v0 式奇偶谜题（撞 0 或 1 次）；目标在轴臂且该色不在本中心 ⇒ **强制搬运**（该色不可能凭空出现在轴臂上）。两类目标可同关混用。
- 推论 2：垂臂颜色**永远到不了**同中心的轴臂（垂臂只与垂臂互换）；轴臂 A 的颜色到对面轴臂 B 用空手翻转即可（奇偶）。
- 推论 3：同中心「自搬运」被结构排除——手中颜色永远来自当前开口臂，不可能凭自己把垂臂颜色搬进插槽。跨中心输入是唯一通路。
- 推论 4（手持不变式，11–15 制关中推导）：**手持一旦非空永不为空**——拾取、场珠交换、进攻换出都只是替换手中颜色 ⇒ 「空手翻转」的机会只存在于开局（第一次拾取之前）。空手类谜题本质是开局顺序谜题。
- 推论 5（提取槽）：每次进攻的提取槽 = 当前开口方向那条臂（轴臂），开口在两条轴臂间交替 ⇒ 垂臂内容永不可提取；起始在**非开口侧**轴臂上的颜色每次进攻都被甩到新的非开口侧，同样永不可提取。每个中心「初始可提取的颜色」至多一种（开口臂上那枚）；其余只能靠玩家先投放再取出。

取舍记录：

- 离去基团去向：「落到攻击者身后」（v0 简化声明草图）→ 改为「**进攻击者手中**」。落点版必须定义墙 / 边界 / 中心 / 占用格的回退规则，规则重量大；换手版一句话可解释，且天然构成「取货—送货—换货」物流链。落点版（弹射）保留为后续「新规律」候选。
- 不加「主动丢弃」动作：动作空间保持四方向（solver 分支不膨胀）；丢弃用「走上另一基团格交换」表达，且判胜不关心手中物，丢弃无必要性。

### v3 机制群：广撒网批次（2026-08-24 决策）

**背景**：v2 复测前的产品决策——把头脑风暴产出的机制按关卡曲线**全部落地体验**，宁可多做、试玩后再删（2026-08-24 与玩家的共同决定）。选择标准见头脑风暴存档（iteration #6 后续）：每条机制要么引入一条新定理，要么精准打破一条旧不变式。本轮刻意**不做**两条深水区机制：空臂消除（推翻目标系统）与手性棋盘（状态/渲染翻倍）——需要独立验证周期，定题后再评估。

七条机制（21–40 关分批教学）：

1. **光照格（打开口轴）**：关卡可声明 `lights: [pos]`。玩家**走入**光照格的一瞬，**所有中心**的开口方向顺时针转 90°（N→E→S→W→N；三元中心在自己的三方向内轮转，见 7）。只转开口、不动臂色、不消耗额外回合（就是那一步移动）。**打破开口轴不变式**——01–20 的最强结构定理从此不再绝对。设计用「全局生效」而非逐格指定目标：规则一句话可懂，代价是多中心关卡里每次照光都牵一发动全身（这正是谜题）。
2. **回收格（打破手持不变式）**：`disposals: [pos]`。手持色珠走上回收格 ⇒ 色珠销毁、手变空。空手走上无效果。「空手翻转」从开局限定变成**可再生的中盘资源**。
3. **保护基与脱保护格**：中心可声明 `shielded: true`（渲染为防护罩）。被保护中心：进攻无效、**共振也传不进去**（链在罩前停下——保护基因此兼任「连锁闸门」）。`deprotections: [pos]`：首次走上脱保护格，全场保护**永久**解除（状态位，进 stateKey）。玩法 = 先干别的、最后解锁的次序规划。
4. **分步目标（反应中间体）**：关卡可声明 `stages: [{goals}...]` 替代 `goals`。按顺序逐段达成：当前段所有目标同时满足 ⇒ 进入下一段（一步可连进多段）；全部段完成 = 胜利。`stage` 进 stateKey（它影响转移，不是纯计数器）。旧关无 stages ⇒ 规约为单段，行为不变。渲染：当前段目标正常虚线圈，未来段目标以淡圈预告。
5. **弹射中心（离去基团落到棋盘）**：中心可声明 `ejects: true`。持珠进攻它：携带珠照常注入（手变空），被顶出的基团**不入手**，而是沿攻击反方向从玩家身后飞出，落到射线遇到的第一个障碍前一格（墙/中心/其他色珠/边界）；身后第一格就被堵 ⇒ 进攻无效。空手进攻仍是纯翻转。搬运关从「手持物流」升级为「弹道规划」。
6. **弹射台（远程取代）**：`launchers: [{pos, dir}]`。**手持**色珠走上弹射台 ⇒ 色珠沿 dir 直线飞出（手清空）：命中中心时，若方向恰为其开口 ⇒ 发生取代——色珠装入、被顶出的基团落回色珠**刚离开的格子**（交换远程发生，必然合法）并触发共振；方向不合 / 命中保护罩 ⇒ 色珠停在该中心前一格变游离珠；命中墙 ⇒ 停在墙前一格；飞出棋盘 ⇒ 停在最后一格。动作空间不变（仍是四方向移动）。
7. **三元中心（mod 3）**：中心可声明 `kind: 'trigonal'`：只有 N/E/S 三臂（无 W 臂），进攻 = **三臂轮换**（N→E→S→N 顺时针）而非 180° 对换，开口同向轮转。构型周期从 2 变 3（**打破奇偶锁**）。持珠进攻的落臂 = 开口的「下下家」（leaving 顺时针两格：N→S、E→N、S→E），提取槽仍是开口臂。三元中心不与西侧邻居共振（没有 W 臂）。渲染为三角骨架、120° 语义的轮换动画。
8. **标准杆（非机制）**：关卡可选 `par`（设计最短解）。HUD 显示标准杆，胜利时按步数给 ★★★（≤par）/★★（≤par+3）/★。只读信息，不进引擎状态。

结构注记（后续制关的基石）：

- 「同时性目标」不需要引擎改动——现有判胜本来就是「同一回合末全部满足」；它是**关卡设计手法**：把两个目标构造成只能被同一次连锁同时点亮（37 关）。
- 光照格转的是**开口**不是臂色 ⇒ 它改变的是「谁能从哪里被进攻」与奇偶时序，不改变共振链的颜色通断——两类谜题正交，可叠加。
- 回收格 + 弹射中心互补：前者销毁、后者产出，场珠总量从此可增可减，11–20 的「颜色守恒」直觉失效。
- 保护罩是**唯一能挡住共振**的东西 ⇒ 「链闸」是 36 关起的新元件。

### v2 新规律：共振传导（2026-08-24 决策）

**背景**：v1 复测反馈——搬运的空间深度成立，但仍缺「一击改变多个中心」的连锁爽感；玩家明确要求连锁反应、并希望更多借有机化学的意象。决策：把原排在 21–30 段的第一条「新规律」提前到 16–20 段，选用**共振传导**（共轭体系的抽象）。

规则：

1. 两中心正交相邻（曼哈顿距离 1）时，它们通过彼此面对的两条臂相连（渲染上画成键）。
2. 每当一个中心 X 被翻转（玩家进攻或共振传播所致），检查 X 的四邻：对每个**本次连锁中尚未翻转**的相邻中心 Y，若 X（翻转后）面对 Y 的臂色 == Y 面对 X 的臂色 ⇒ Y 自动翻转一次（**纯翻转**：180° 对换 + 开口反向），随后以 Y 为源继续传播。
3. 一次进攻引发的连锁中每个中心至多翻转一次（保证终止）；传播不触碰手持与场上色珠。
4. 传播顺序：队列 FIFO、邻居按 N/E/S/W 枚举。**结果与顺序无关**：每个中心至多翻一次且翻转是固定变换——顺序只影响观感（渲染按传播距离做阶梯动画）。
5. 完全向后兼容：01–15 无相邻中心，规则从不触发；动作空间、`stateKey`、solver 零变化。

化学映射：共轭 π 体系 / 共振传播——面对臂同色 = 共轭接通，一处反应（翻转）沿共轭链传导。

结构性质（制关基石）：

- 连锁判定用**翻转后**的颜色 ⇒ 链的接通状态随每次翻转重新计算，「多米诺式逐级接通」成为核心谜题元素（17 关）。
- **链环颜色不可投放定理**（16–20 制关中证明）：面对相邻中心的臂永远无法成为投放落点（投放站位被邻居中心占据）⇒ 玩家对点火的控制权只能是**翻转奇偶**，不能是颜色投放；「配平」类设计全部退化为奇偶设计，这是本规则下关卡深度的真实来源。
- **奇偶点火**：面对臂颜色在每次翻转时与对侧臂互换 ⇒ 链在奇/偶数次翻转间交替通断；同一中心连续进攻可依次点燃不同方向的链（20 关）。
- **回火**：被传导翻转的中心会以新颜色重新检查邻居 ⇒ 设计不当会让连锁弹回、摧毁已达成目标（20 关初版因此返工：需保证「翻转后的面对臂色 ∉ 邻居后续所有奇偶态」）。
- 夹在两个中心之间的链中间中心天然不可直接进攻（站位被邻居占据），只能被共振改变——「只能通过连锁到达的中心」是新的关卡元件。
- 共振是双刃剑：链尾若挂着已达标中心，错误的奇偶时序会把震动烧过去（19 关的负面用法）。

取舍：

- 消除（anti-periplanar）继续预留：需引入「空臂」概念，规则重量大；共振复用既有状态、零新概念，风险×收益更优。
- 「离去基团落点（弹射）」版本继续预留（见 v1 取舍）。

### v0 结构性上限：构型奇偶性（2026-08-23，制关中确认）

- 每次进攻都是同一个 180° 对换 ⇒ 每个中心只有「初始 / 翻转后」**两种构型**（周期 2）。
- 推论 1：某中心的目标要么恰好 1 次进攻可达（奇数次），要么初始已满足（偶数次 = 0 次，即「别碰它」）。「连续翻转达到目标朝向」在 v0 下**不存在**，§6 曲线 06–10 段改由路线长短、进攻顺序、「别碰已达标中心」提供深度。
- 推论 2：目标按奇偶构造 ⇒ 需要翻转的中心必然至少被撞一次，**背面进攻机制不可能被绕开**（天然满足 §7 的过滤标准）。
- 推论 3：连续翻转的组合空间只能由正式规则（基团搬运或新的翻转维度，见上方简化声明）解锁——这是「第 5 关测试」定题的关键输入之一。
- **2026-08-24 更新**：v1 基团搬运落地后，轴臂成为可任意注入颜色的插槽（见 v1 规则「轴臂 = 插槽，垂臂 = 奇偶锁」），本上限**只对垂臂目标继续成立**（且是刻意保留的设计维度，不是缺陷）。

## 7. AI 关卡 pipeline（评审重点）

目标：展示「AI 协作完成游戏设计」，而不只是 AI coding。

```
LLM 生成候选关卡 JSON
  ↓ zod 校验（结构/边界/重叠）
  ↓ Solver（BFS）验证有解 + 求最短解
  ↓ 过滤：过于简单 / 存在绕开核心机制的捷径 / 目标机制未被实际使用 / 解过长
  ↓ LLM 对有趣程度评分 + 与关卡设计意图比对
  ↓ 人工试玩
  → 最终关卡入库
```

迭代证据要留档（写进 `iteration.md`）：某关初版被 solver 发现绕开了目标机制 → 修改墙体 → 若干轮迭代后机制成为必选。这类「预期机制 vs 实际最短解」的对比是答辩时最有说服力的材料。

当前已具备：
- zod 校验（各游戏 `level.ts`）、通用 BFS solver（`src/core/solver.ts`）、命令行验证（`pnpm solve`）。
- 构造-验证工具 `scripts/craft-t3.ts`（`pnpm craft:t3 <spec.json>`）：从「预期解序列 + 起点 + 墙」正向构造关卡并用 solver 核对（对应上面流程的「生成 → zod 校验 → Solver 验证」三步）。
  人工设计关卡时也走这条路径，保证「预期解可行」与「最短解长度符合意图」都有机器证据。

尚缺：LLM 直接生成候选关卡、有趣程度评分标准、关卡批次管理工具。

| --- | --- | --- |
| 框架 | **无框架**（vanilla TS + Vite） | 回合制确定性谜题没有框架要解决的问题；时间紧，配置成本零收益 |
| 渲染 | Canvas 2D | 棋盘小、动画自由度高；DOM 方案亦可但补间/特效受限 |
| 引擎形态 | 纯函数 `step(state, action) → state`，状态不可变且完全可序列化 | 免费获得：撤销、重放、Node 侧 solver 复用（三者都依赖状态即数据） |
| 游戏接入方式 | 统一 `GameDefinition` 协议（parse / initial / actions / step / isWin / stateKey） | 双原型共用骨架；未来新机制原型接入成本极低；solver 与协议是同一份设计 |
| 关卡数据 | JSON + zod 加载期校验 | AI 生成的脏关卡在加载时报错，而不是渲染时崩溃 |
| 运行时依赖 | 仅 `zod` | 比赛风险控制 |
| `stateKey` 约定 | 唯一状态标识，**不含步数等纯计数器** | solver 去重与撤销判空都依赖它；含计数器会导致搜索无法剪枝 |

## 10. 命名与视觉包装方向

### 命名（已定）

| 原型 | 正式名 | 理由 |
| --- | --- | --- |
| t3 | **《t+3》** | 名字即规则：你按下的每个键，都会在 t+3 时刻再次生效。标题画面就是 `t + 3 [START]`，零解释成本；数字可随时间层扩展（+2 / +4 / +6）「长大」 |
| chem | **《109.5°》** | 四面体键角——只有懂化学的人才认得出的 nerd 符号，与《t+3》构成「符号双联」；游戏内不出现任何化学术语，标题是第一个揭晓点 |

命名原则：**短**（标题画面就是一行字）、**能当教学用**（名字 + 一句话就能懂）、**留彩蛋位**（第二层含义留给答辩揭晓）。

### 视觉包装方向

比赛不要求故事与美术包装，但我们做**轻包装**：一切包装用排版、配色与程序化图形（Canvas）实现，零美术素材。

- 总体气质：极简 + 微科幻。等宽字体、深色底、细线条、克制的霓虹点缀；HUD 走「仪表」风格（步数、回声队列、开口方向等以读数形式呈现）。
- **玩法标记的可读性纪律（2026-08-24 试玩反馈）**：抽象的白色圆圈会被误读为渲染 bug——玩法标记必须自带方向/语义（开口用「朝外的白色箭头」、达标用「锁定圈 + ✓ 徽标」）。新增玩法标记时先问：不看文档能猜出含义吗？
- **《t+3》偏科幻 / 时间感**：时间线 / 刻度元素，回声以半透明「残影」+ 轨迹呈现，输入队列显示得像指令缓冲区。
- **《109.5°》偏化学味**：中心画成分子骨架风格（键线 + 原子点），背景可出现极低透明度的四面体线框，HUD 点缀刻度般的实验仪器感；**全程仍不出现化学式文字**。
- 标题画面：大字（`t + 3` / `109.5°`）+ 极简程序化动效（残影缓慢回放 / 四面体缓慢旋转），几十行 Canvas 即可。
- 纪律：包装不得干扰谜题可读性——装饰元素不许压棋盘，且可用一个开关整体关掉。

### 玩家辅助：solver 提示（2026-08-24 决策）

试玩反馈：部分关卡卡死后没有出路，玩家做不出来。决策：**提示直接复用通用 solver**，不写手打攻略。

- 壳层「下一步提示」按钮（H 键）：从**当前局面**跑一次通用 BFS（`core/solver.ts` 新增 `solveFrom(def, state, opts)`，引擎零改动），取解的第一步，以「下一步：→（向右）」的浮层展示；每次按都从最新局面重新求解，可以一步步连着要提示。
- 三种结果三句话：可解 → 给下一步；**不可解**（如回收格扔掉了必需的珠子、t+3 把队列搅死）→ 明说「这个局面走不通了，撤销 (Z) 或重开 (R)」——死局检测本身就是教学；求解被截断 → 退回展示本关文字提示。
- 为什么不做多级提示（先暗示再给答案）：时间紧，solver 方案一步到位、对两个游戏通用、零维护成本；玩家想自己憋可以不用它。提示不消耗任何东西、不计入任何评价（星级只看步数与标准杆），鼓励卡住就用。
- 成本上限：提示的 BFS 从当前局面出发，剩余深度 ≤ 通关深度；沿用 `maxDepth 30 / maxVisits 500k`，单关实测毫秒到百毫秒级，同步执行可接受（不做 Web Worker，避免过度工程）。
