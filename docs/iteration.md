## #0 2026-08-23 — 仓库骨架与双原型 v0

- 改了什么：
  - 建立仓库骨架：`src/core`（GameDefinition 协议、通用 BFS solver、撤销栈、关卡加载、键盘映射、补间工具）、`src/games/t3`、`src/games/chem`、`src/shell`（游戏切换 / HUD / 撤销 / 重开）。
  - 两个原型各实现 v0 规则与关卡 1：
    - `t3`：当前棋子 + 延迟 2 的红色回声棋子，同时到达各自目标格获胜；被墙挡住的输入仍消耗回合并进入回声队列。
    - `chem`：单中心四臂 + 开口臂；背面进攻成功触发四臂 180° 对调、开口臂翻转（占位规则，见 design §5 简化声明）。
  - 建立文档体系：`docs/design.md`（设计思路，含候选方案淘汰记录、双原型规则定义、50 关曲线、AI pipeline）、本文件（迭代演进）、`AGENTS.md`（协作规范，含文档维护硬性要求）。
  - 工具链：Vite + TS(strict) + vitest + zod；`pnpm solve` 命令行 solver。
- 为什么：比赛时间紧，先用同一骨架并行验证两个候选机制（「第 5 关测试」定题），骨架与 solver 无论哪个胜出都不浪费。
- 如何验证：`pnpm typecheck` / `pnpm test`（引擎手动解、阻塞回合、solver 最短解）/ `pnpm build`；`pnpm solve t3 level-01` 与 `pnpm solve chem level-01` 均可解。
- 遗留问题：
  - 两个原型都只有 1 关；下一步各手画 5 关跑测试。
  - `chem` 是占位规则，正式化需重设计（基团搬运等，见 design §5）。
  - `t3` 棋子碰撞规则未定（v0 允许重叠）。
  - 渲染暂无补间动画（`core/tween.ts` 已备好）。

## #1 2026-08-23 — 命名定稿与视觉包装方向

- 改了什么：
  - 双原型正式命名：`t3` → **《t+3》**、`chem` → **《109.5°》**（四面体键角），构成「符号双联」；命名理由与原则见 design §10。
  - 确定视觉包装方向：零美术素材的轻包装（排版 + 配色 + 程序化 Canvas 图形）；《t+3》偏科幻/时间感，《109.5°》偏化学味（分子骨架风格，但游戏内仍不出现化学术语）。
  - 同步更新 `README.md`、`AGENTS.md` 与 shell 标签。
- 为什么：比赛不要求剧情与美术，但需要最基本的辨识度与答辩记忆点；名字本身承担一半教学功能，化学梗留给答辩揭晓。
- 如何验证：纯文档与标签变更，不影响引擎行为。
- 遗留问题：标题画面与主题化渲染（残影 / 分子骨架风格）尚未实现，按 design §10 方向排期。

## #2 2026-08-23 — 《t+3》教程批次 01–10 + 构造验证工具

- 改了什么：
  - `t3` 新增 9 关（`level-02` ～ `level-10`），`level-01` 补充教学文案；前 10 关构成完整新手教程曲线（每关只教一件事，细化表见 design §6）：
    | 关 | 教什么 | 最短解 |
    | --- | --- | --- |
    | 01 迟到的同伴 | 发现回声、垫拍等它 | 4 |
    | 02 撞边也算数 | 撞边/撞墙消耗回合，原地踏步 = 等待 | 4 |
    | 03 时差 | 最后两拍未被回声接收，可各走各路 | 4 |
    | 04 绕行 | 绕路被原样重放 | 8 |
    | 05 同键不同路 | 精确安排被墙吃掉的拍子 | 5 |
    | 06 一拖二 | 两枚同延迟回声 | 5 |
    | 07 三层时间 | d2 + d4 双时间层 | 6 |
    | 08 缝隙 | 墙 + d2 + d4，目标倒推路线 | 8 |
    | 09 喂招 | 撞边的拍子成为回声的真实移动 | 6 |
    | 10 四层合奏 | 三回声 d2/d4/d6 组合 | 10 |
  - 关卡格式新增可选 `hint` 字段（t3 与 chem 的 `level.ts` 均已接入；zod 可选），shell 在棋盘外展示（`#level-hint`）。决策与理由见 design §4。
  - 新增 `scripts/craft-t3.ts`（`pnpm craft:t3 <spec.json> [--write]`）：从「预期解序列 + 起点 + 墙」用真实引擎正向构造关卡（末位置即目标格），再自动 zod 校验 + solver 核对。这是 design §7 pipeline「生成 → 校验」环节的第一块实现。
  - 新增 `src/games/t3/levels.test.ts` 批次守护：10 关全部通过校验、可解、最短解长度断言、教程每关必须带 hint 且不得泄露解法序列。
  - **零引擎改动**：多回声、不同延迟完全由关卡数据承担（`echoes[]` 本就支持）。
- 为什么：按 design §6 曲线推进教程批次；构造工具保证「预期解可行」与「最短解符合意图」都有机器证据，供后续 40 关复用。
- 如何验证：`pnpm typecheck` / `pnpm test`（36 tests）/ `pnpm build`；`pnpm solve t3 level-01..10` 全部可解且最短解长度与断言一致。
- 「预期解 vs 实际最短解」留档（pipeline 迭代证据）：
  - level-04 预期 `ENEESEWE`，solver 给出等长变体 `NEEEESNS`（先绕后入的同构绕法）；
  - level-09 预期 `SSSEEE`，solver 给出 `ESSSEE`——「撞边喂招」机制仍是必选，只是喂招前的走位自由；
  - level-10 预期 `WWESEESEEE`，solver 给出另一条 10 步对齐；多解但同深度，说明机制未被绕开。
- 遗留问题：
  - 碰撞规则仍为 v0（允许重叠）：level-08/10 存在棋子同格交错，若将来改互斥需重新验证全批次。
  - level-10 solver 访问约 18 万状态，接近默认上限；后续更深关卡注意控制棋盘规模或调高 `maxVisits`。
  - 11 关起按 design §6 曲线继续（压力板 / 回声瓦片等需要引擎扩展，留给定题后）。

## #3 2026-08-23 — 《109.5°》教程批次 01–10 入库（1 关 → 10 关，零引擎改动）

- 改了什么：
  - 《109.5°》关卡 1 → 10。01–05 教学段：第一次撞入 / 站到背面去 / 读开口方向 / 墙与绕行 / 完整路线规划；06–10 多中心段：两个中心 / 顺序有代价 / 别碰已达标中心 / 房间与门 / 综合毕业（每关教学点见 design §5 批次表）。
  - `hint` 字段在 chem `level.ts` 接入（与 #2 同一决策），全部 10 关均带教学/点拨文案；shell 提示条（#2 的 `#level-hint`）对 chem 生效。
  - 关卡 id 由 `chem-XX` 更名为 `109.5°-XX`：HUD 会展示关卡 id，旧代号在游戏内泄露「化学」字样，违反 design §10「游戏内不出现化学术语、标题是第一个揭晓点」。
  - 新增 `src/games/chem/levels.test.ts` 批次守护：全部关卡 parse 校验 + 初始未胜（无空关）+ solver 可解 + 最短解长度基线断言（1/5/4/7/10/13/13/7/19/20 步）。
  - design §5 记录 v0 **构型奇偶性结构上限**（每次进攻都是同一 180° 对换 ⇒ 每中心仅两种构型），§6 曲线 06–10 段实现方式相应调整——这是「第 5 关测试」的关键输入。
- 为什么：推进「第 5 关测试」——手画关卡验证 v0 机制深度；教程不靠剧情，只靠关卡顺序 + `hint` 点拨。
- 如何验证：`pnpm solve chem level-01..10` 全部可解且最短解长度与断言一致；level-07「顺序有代价」用约束 BFS 单独实测（先撞 A 13 步 / 先撞 B 19 步，顺序差 6 步）；`pnpm typecheck` / `pnpm test`（67 tests 通过）/ `pnpm build`。
- 「预期解 vs 实际最短解」留档：各关手算路线与 solver 最短解一致或等长（如 level-06 南侧路线与 solver 的北侧路线同为 13 步）；机制（背面进攻）按奇偶构造目标，结构上不可绕开。
- 遗留问题：
  - v0 上限下，需要翻转的中心必然恰好撞一次即达标，路线类深度接近极限：11–20 段扩充前需先定正式规则（基团搬运等，见 design §5 结构性上限）。
  - 教程提示为每关静态一条；是否需要分步提示待试玩反馈。

## #4 2026-08-23 — 《109.5°》主题化渲染落地（design §10 化学味方向）

- 改了什么：
  - 重写 `src/games/chem/render.ts`：中心改为分子骨架风格（细键线 + 臂原子 + 中心原子点）；背景加极低透明度（α≤0.06）四面体线框（键角 109.5° 的几何本体，顶点即原子点）；底部 HUD 仪器化（刻度尺 + 步数三位读数 + 开口读数）；棋盘四角加仪器角框。
  - 装饰开关（§10 纪律「可用一个开关整体关掉」）：`setChemDecor()` + shell 头部「✦ 装饰 开/关」按钮；`Bundle.setDecor` 设为可选协议，当前仅 chem 接入。关掉只去除装饰，开口圈 / 箭头 / 目标虚线等玩法信息永远保留。
  - 纪律落实：布局常量不变（装饰不压缩棋盘）；渲染内文案无任何化学术语。
  - 新增渲染冒烟测试 `render.test.ts`（Proxy 桩画布直通单/多中心关卡 + 装饰开关两种状态）。
- 为什么：落地 design §10 轻包装方向；《109.5°》的化学味是答辩揭晓记忆点的一半，标题几何（四面体）先进背景。
- 如何验证：`pnpm typecheck` / `pnpm test`（68 通过，含渲染冒烟）/ `pnpm build`。
- 遗留问题：
  - 《t+3》的科幻/时间感渲染与两游戏标题画面（大字 + 程序化动效）尚未实现。
  - 装饰按钮当前只对《109.5°》生效（t3 未实现 `setDecor` 前为无操作）。
  - 渲染为静态帧（无 rAF 循环），背景四面体不旋转；若后续要动效需先给 shell 加渲染循环。
