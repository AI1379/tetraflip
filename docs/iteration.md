## #0 2026-08-23 — 仓库骨架与双原型 v0

- 改了什么：
  - 建立仓库骨架：`src/core`（GameDefinition 协议、通用 BFS solver、撤销栈、关卡加载、键盘映射、补间工具）、`src/games/t3`、`src/games/chem`、`src/shell`（游戏切换 / HUD / 撤销 / 重开）。
  - 两个原型各实现 v0 规则与关卡 1：
    - `t3`：当前棋子 + 延迟 2 的红色回声棋子，同时到达各自目标格获胜；被墙挡住的输入仍消耗回合并进入回声队列。
    - `chem`：单中心四臂 + 开口臂；背面进攻成功触发四臂 180° 对调、开口臂翻转（占位规则，见 design §5 简化声明）。
  - 建立文档体系：`docs/design.md`（设计思路，含候选方案淘汰记录、双原型规则定义、50 关曲线、AI pipeline）、本文件（迭代演进）、`AGENTS.md`（协作规范，含文档维护硬性要求）。
  - 工具链：Vite + TS(strict) + vitest + zod；`pnpm solve` 命令行 solver。
- 为什么：比赛时间紧，先用同一骨架并行验证两个候选机制（「第 5 关测试」定题），骨架与 solver 无论哪个胜出都不浪费。
- 如何验证：`pnpm typecheck` / `pnpm test`（引擎手动解、阻塞回合、solver 最短解）/ `pnpm build`；`pnpm solve t3 level-01` 与 `pnpm solve chem level-01` 均可解。
- 遗留问题：
  - 两个原型都只有 1 关；下一步各手画 5 关跑测试。
  - `chem` 是占位规则，正式化需重设计（基团搬运等，见 design §5）。
  - `t3` 棋子碰撞规则未定（v0 允许重叠）。
  - 渲染暂无补间动画（`core/tween.ts` 已备好）。

## #7 2026-08-24 — 《109.5°》v3 机制群 + 21–40 批次（广撒网，试玩后再删）

- 改了什么：
  - **引擎 v3（design §5「v3 机制群」决策落地）**：7 条新机制——光照格（全场开口顺时针转轴，三元中心在三方向内轮转）、回收格（销毁手持，打破手持不变式）、保护基 + 脱保护格（罩住的中心进攻无效、共振不入 = 链闸；脱保护永久）、分步目标（`stages` 按段推进，一步可连进多段，旧 `goals` 规约为单段）、弹射中心（携带珠注入、顶出物沿反方向飞出，手变空）、弹射台（手持走入沿台面方向发射，远程取代时顶出物落回珠刚离开的格子）、三元中心（三臂轮换 mod 3，落臂 = 开口的下下家）。另加标准杆 `par`（纯展示 + 通关星级）。
  - **关卡 21–40 入库**（教学序列与基线 6/13/6/7/7/9/5/9/9/10/11/3/9/4/3/11/5/8/7/21 见 design §5 批次表）。全部 `pnpm solve` 验证 + 关键关 `pnpm trace:chem` 逐帧比对。
  - **渲染**：特殊格视觉（光照=金色放射纹呼吸 / 回收=虚线井口下箭头 / 脱保护=开锁 / 弹射台=双箭头）、保护罩六边形、三元中心三角骨架 + 沿弧轮换动画（非刚体旋转）、分步目标当前段亮圈 + 未来段淡圈预告、HUD 标准杆/段数/通关星级；连锁阶梯动画兼容新机制（光照只转开口不播翻转动画）。
  - **测试**：引擎 33 项（每条机制语义 + 回归），渲染冒烟覆盖全部 v3 视觉路径，关卡基线扩到 01–40（共 190 项测试全绿）。
- 为什么：玩家决策「机制多做、多体验、回头再删」——把头脑风暴的推荐档 + 次选档 + 深水区里的三元中心全部落地，用试玩反馈决定 41–50 段保留哪些。刻意不做空臂消除（推翻目标系统）与手性棋盘（状态翻倍），留独立验证周期。
- 制关证据与返工记录：
  - **弹射中心重复色 bug**：初版「手持不变」让携带珠注入后仍留在手里（颜色无中生有），引擎测试抓到，改为注入后手变空。
  - **翻转双轴定理再踩坑**：23 关首版按「只翻进攻轴」手算链色，实际翻转是 N↔S + E↔W 全对换——连锁同色条件全部重推。教训：链色一律以 solver/trace 为准，不手算。
  - **手持强制注入再现**（28 关）：A 先行方案被 A 换出的手持物砸坏 C 的目标，唯一序是空手先做中间体——与 19 关同构，确认为本规则族的稳定深度来源。
  - **目标初始即真陷阱**（36 关）：「翻转后复原」类目标初始就满足，被 7 步绕过；重设为「先撞立目标 → 解锁 → 反向连锁」。
  - **40 关 solver 优于设计**：solver 用顶出的蓝珠当周转换黄珠（换珠机制自现），21 步与设计基线一致但路线更精彩——保留并记录。
  - 站位几何再确认：开口 d 的站位 = 中心 − DIR_VEC[d]，进攻方向 = d（v2 期已定型，本批 20 关全部按此复核）。
- 如何验证：`pnpm typecheck` / `pnpm test`（190 项）/ `pnpm build`；21–40 全部 solver 可解、最短解与基线一致；22/23/24/26/28/31/33/36/38/40 经 trace 逐帧确认教学动作真实发生（回收、弹射落点、链闸、连锁、分步推进、发射×2）。
- 遗留问题：
  - 试玩反馈后做**机制删减**：候选观察点——弹射台与弹射中心是否冗余、三元中心的心算负担是否过重、标准杆星级是否有人看。
  - 41–50 段等删减结论后再排（组合深化或补新机制）。
  - 胜利回放 / 标题屏（包装项）未做。
  - AI 关卡 pipeline（§7）该启动了：50 关指标里 t3 仍只有 10 关，chem 40 关已验证的规则结构（奇偶/轴/链）适合模板化生成。

## #6 2026-08-24 — 《109.5°》v2 共振传导 + 16–20 批次 + 白圈 UI 修正

- 改了什么：
  - **引擎 v2（design §5「共振传导」决策落地）**：正交相邻且面对臂同色的中心连通；任一中心被翻转后，震动沿连通链传导纯翻转，一次连锁每中心至多翻一次、结果与传播顺序无关。进攻判定、动作空间、`stateKey` 零变化；01–15 无相邻中心 ⇒ 完全向后兼容（旧基线一步未变，测试证实）。
  - **关卡 16–20 入库**（教学序列与基线 4/7/14/14/16 见 design §5 批次表）：共振发现 / 多米诺逐级接通 / 奇偶点火 / 断链（危险色珠）/ 奇偶序列点燃双链。全部 `pnpm solve` 验证 + `pnpm trace:chem` 逐帧比对设计意图。
  - **UI 修正（试玩反馈：白色圈圈像 bug）**：开口标记由「白圈」改为**朝外的白色箭头**（自带方向语义；`level-01` hint 同步改写）；达标锁定圈加 **✓ 徽标**；相邻中心画**共轭键**（面对臂同色时点亮脉动，否则暗色）、相邻臂缩短避让、面向相邻臂的目标虚线圈移到半程位置；连锁翻转动画按传播距离阶梯延迟（每级 90ms）。
  - 测试：引擎新增 6 项共振语义测试（翻后判定 / 不通不传 / 多米诺 / 纯翻转不动手持 / 连锁按进攻重置）；渲染冒烟覆盖相邻中心与连锁转移；关卡基线扩到 01–20。
- 为什么：试玩反馈两条——①白圈无法理解、疑似 UI bug（玩法标记必须自带语义）；②携带机制仍不够有趣，要求连锁反应并多借鉴有机化学。共振 = 共轭体系的抽象，是 design 里原排 21–30 段的第一条「新规律」，提前到 16–20 落地。
- 制关中证明的结构定理与返工记录（已写入 design §5）：
  - **链环颜色不可投放定理**：面对相邻中心的臂永远无法成为投放落点（站位被邻居占据）⇒ 点火控制权只能是翻转奇偶。level-18 初版「先配平再点火」因此整体重构为「奇偶点火」。
  - **手持强制注入**：进攻必然把手中之物注入目标 ⇒ level-19 初版终点进攻被手持蓝珠砸坏 A 目标，A 目标改为「强制注入色」后反而强化了断链教学。
  - **双翻恒等式**：同中心两次翻转 + 无净投放 = 恒等 ⇒ level-20 初版「自提取物流」被 solver 用全空手双翻 14 步绕过；重构为「奇偶序列点燃双链」。
  - **回火**：被传导的中心会以新颜色复查邻居 ⇒ level-20 二版中 X1 被偶次翻转回火摧毁，改配色保证「翻后面对臂色 ∉ 邻居后续奇偶态」。
- 如何验证：`pnpm typecheck` / `pnpm test`（116 项全绿，含 01–15 旧基线回归）/ `pnpm build`；16–20 全部 solver 可解、最短解与断言一致、trace 回放确认连锁/奇偶/断链按设计发生。
- 遗留问题：
  - 21–30 段候选（anti-periplanar 消除 / 弹射落点）未动；「消去」需要空臂概念，规则重量待评估。
  - 共振连锁的动画阶梯只按中心距离近似传播顺序（渲染层未拿引擎的真实传播序）——观感正确、语义近似，暂不修。
  - 白圈修正后需要再找试玩确认箭头/✓/共轭键的可读性。
  - 「第 5 关测试」复测结论仍待人工试玩：共振是否让《109.5°》追平 t3 的「每关一个新理解」。

  - **引擎 v1（design §5 正式规则落地，v0 简化声明预留的方向）**：关卡可声明游离色珠 `groups: [{pos,color}]`；走上色珠格拾取、持物再走上则交换（动作空间仍为四方向）；空手进攻 = v0 纯翻转（旧关完全兼容）；持色珠进攻 = 取代 + 翻转（色珠装到正对攻击者的臂、开口臂旧色换入手中）。目标校验放宽为「颜色存在于本关任一臂或色珠」。`stateKey` 纳入手持与场珠。
  - **关卡 11–15 入库**（v1 复测批次，教学序列见 design §5 批次表）：11 拾取投放（6 步）/ 12 跨中心取送（11）/ 13 循环交换（17）/ 14 两种目标·空手一击时机（18）/ 15 毕业题·共享站位（16）。全部经 `pnpm solve` 验证，最短解断言进 `levels.test.ts`（批次 01–15，47 项）。
  - **渲染手感三件套**（`render.ts` 重写 + `shell/main.ts` 加渲染循环）：行走补间与翻转 180° 旋转动画（`core/tween.ts` 首次接入；动画状态是渲染层私有时钟，按 stateKey 转移驱动，大跳/换关自动重置）；无效进攻抖动 + 撞面红闪（`Bundle.onBlocked` 钩子）；已达标中心锁定圈（「别碰已达标」一眼可见）；另画游离色珠与手持色珠、HUD 加「手持」读数、背景四面体缓慢自转（shell 现在常驻 rAF 循环）。
  - 新工具 `scripts/trace-chem.ts`（`pnpm trace:chem <level-XX>`）：逐帧回放最短解（玩家/手持/各中心臂与开口/达标状态），「预期解 vs 实际最短解」比对正式工具化。
- 为什么：01–10 试玩反馈确认 v0「进攻 = 纯翻转」的奇偶上限是无聊根源（每中心仅 2 种构型，谜题退化为路线 + 拨开关）。v1 把进攻从「拨开关」升级为「搬运 + 交换」：轴臂成为可注入颜色的插槽，构型空间爆炸，移动有了取货—送货—换货的目的性；11–15 即「第 5 关测试」的复测材料。
- 制关中推导并验证的两条新结构不变式（已写入 design §5 推论 4/5）：
  - **手持不变式**：手持一旦非空永不为空（拾取/交换/进攻都只替换手中颜色）⇒ 空手翻转的机会只在开局，空手谜题是开局顺序谜题。level-14 就是按此构造：P 双目标（armE=blue + armW=red）只有空手一击能同时达成，任何携带物都会砸坏 armW。
  - **提取槽**：每次进攻的提取槽 = 开口方向那条臂，且开口只在两轴臂间交替 ⇒ 垂臂内容永不可提取、起始在非开口侧轴臂上的颜色也永不可提取（每次进攻都被甩回非开口侧）；每个中心「初始可提取」的颜色至多一种。
- 「预期机制 vs 实际最短解」留档（两次返工，pipeline 证据）：
  - **level-15 返工**：初版 C2 目标 armE=yellow、意图「空手翻转转开口 → 再投放」。solver 最短解（27 步）把「别碰」的 C1 当**颜色提款机**：先持黄撞 C1 换出红、空手期用红撞 C2、再持红撞 C1 复原并取回黄、最后投黄——即「先空手翻转」路线根本不存在（持黄撞 C2 会把黄埋进 W 臂成死循环）。返工：C2 改为一击必中的翻转目标（armE ← 旧 armW，与手持无关），毕业题变为 拾蓝 → 共享站位向南投放/换黄 → 顺路一击，16 步，C1 全程不碰。
  - **level-14 返工**：初版意图「空手撞 P」但 P 单目标 armE=blue——回放发现 armE ← 旧 armW 与手持无关，solver 直接持珠撞 P 也达标，「空手」教学是假的。返工：P 加第二目标 armW=red，携带物会砸坏它 ⇒ 空手一击被手持不变式强制为开局第一动（先空手翻转 → 再拾珠 → 取蓝 → 送蓝，18 步，顺序完全唯一）。
- 如何验证：`pnpm typecheck` / `pnpm test`（94 项，含 v1 引擎语义、01–15 基线、渲染冒烟覆盖动画转移与撞击反馈）/ `pnpm build`；11–15 全部 `pnpm solve` 可解且最短解与断言一致；trace 回放逐帧核对与设计意图一致。
- 遗留问题：
  - v1 规则深度只验证到 5 关；16–20 段（搬运 × 路线 × 多中心组合）与 21–30 段（anti-periplanar 消除 / 弹射变体）待定题后推进。
  - solver 在 v1 下状态数上升（level-15 约 2.4k 访问，仍远低于上限）；后续大关注意 `maxVisits`。
  - t3 渲染仍未接动画循环（shell rAF 已就绪，`setDecor`/`onBlocked` 钩子 t3 未实现，为无操作）。
  - 「第 5 关测试」复测结论待人工试玩：v1 后《109.5°》的组合空间是否追平 t3 的「每关一个新理解」。
